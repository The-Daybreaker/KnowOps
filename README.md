# KnowOps：给 AI agent 用的 Obsidian 知识管理技能包

**English**: [README.en.md](README.en.md) · **中文**：本文件

KnowOps 是一套装给 AI agent 的 Obsidian 知识管理技能。装好之后，agent 就知道该怎么帮你打理知识库：灵感冒出来时随手先记下，不用想该归到哪；等你有空说一声，它再按你定的规矩把记录整理归位；真正验证过的经验，会慢慢沉淀成一篇篇可以反复翻阅的主题文档——而你当初怎么说的，原话就怎么留在里面，一个字都不会被替你改写。

它由两个 skill 组成，按设备安装、互相配合：

| Skill | 装在哪 | 做什么 |
|---|---|---|
| **knowops** | 电脑（能操作知识库的设备） | 知识库的总管：内容怎么组织、Obsidian 怎么操作都归它，单装它就能把整个库管起来 |
| **everywhere-note** | 手机 / 平板等随身设备 | 随身速记员：@ 一下直接口述，它整理成一条规范笔记，晚上提醒你回电脑收进库 |

> 两个 skill 不要装在同一台设备上，否则会争抢同一类触发。

一条记录从随口说出到沉淀为经验，大致是这样一趟旅程：

```text
【手机 / 平板】
  @everywhere-note 直接口述
        │  整理成一条规范笔记，当晚 22:00 提醒你处理
        ▼
【你的电脑】汇集内容：你直接粘贴 / 给文件，或让它从 GitHub 暂存库自动拉取
        │
        ▼
  00 收件箱 —— 随手丢，零讲究
        │  你说「审阅收件箱」，agent 逐条定去向
        ├─▶ 归并进 01 知识等模块（验证过的经验）
        ├─▶ 移入 04 归档（不再活跃，按日期存放）
        ├─▶ 删除（进系统回收站，可恢复）
        └─▶ 还没想清楚 —— 继续留在收件箱
```

## 它是怎么帮你打理知识库的

这一节顺着日常使用的顺序，讲讲你实际会经历什么，以及为什么是这样安排的。

### 记的时候，什么都不用想

知识库用不起来，往往不是因为没东西可记，而是记的那一下太麻烦：要先选分类、要按格式写、要想起名规则，一犹豫，灵感就过去了。KnowOps 把这些事全部从你身上挪走。在电脑上对 agent 说一句「记一下」，或者自己在 `00 收件箱` 里新建个文件，都不需要填格式、不需要先想好标题，随手丢进去就行。agent 写入的条目会自动带好序号和属性，方便你之后浏览；你自己手写的内容则没有任何要求，收件箱也不做格式检查。

分类被特意推迟到了整理的时候。记录的当下信息往往不全，急着归类很容易分错——agent 拿着只言片语也一样会分错；等一条内容完整地摆在面前再判断它属于哪，要靠谱得多。所以在记录这一端，你唯一要做的就是把东西留下来。

手机上也一样轻松。@ 一下 everywhere-note 直接口述，它会把内容整理成一条规范笔记给你核对，当天确实有记录，就帮你设一个晚上 22:00 的提醒，免得忘了回电脑处理；内容怎么传回电脑随你选，可以自己粘贴，也可以指定一个 GitHub 仓库当中转，让电脑端自动拉取，后面会讲到。

「记的时候什么都不用想」不等于什么都往里记。待办事项更适合待办软件，项目资料本来就该待在项目文件夹，能运行的模板属于对应的代码仓库——这些内容在知识库里再存一份，只会变成迟早过时、还得费力同步的副本。这个库留给的是另外一些东西：读到的摘抄、被验证过的经验、还没想清楚的念头。判断一条内容该不该进库，其实就两个问题：它在别处有没有更合适的家？它能不能用一篇笔记讲清楚？

### 整理时，规矩由你定

等你有空了，说一句「审阅收件箱」，agent 就逐条过一遍、按内容定去向：属于某个主题的经验，归并进对应的主题文档；不再活跃的，移进按日期归档的文件夹；确认没用的，删掉并进系统回收站（能恢复）；还没想清楚的，继续留在收件箱。日期、标签这类缺失的信息，它会在这时候补齐。

它凭什么知道每条该去哪？凭的是你自己库里的一份《用户手册》。每个模块装什么、内容怎么入库、怎么分类、怎么命名，规则都写在 `03 系统/用户手册.md` 里，你随时能打开看、动手改；agent 每次干活之前都会先读它，照你的规矩来。规则只此一份，配置文件里只存机器用得到的目录索引，不会出现两处规则对不上的情况。

想新开一个模块，也用不着等任何人更新技能。你在库里建个文件夹（比如「读书」），告诉 agent 它是做什么的、什么内容算它的、内部怎么分，它问清楚后就把规则写进手册、在看板上加好入口，之后一律照此执行。哪天你删掉了这个文件夹，它也会来问你：手册里的规则是一并删掉，还是标注停用、保留历史。知识库长成什么样子由你说了算，skill 提供的只是一套通用的运转方式。

### 经验沉淀成主题，原话原样保留

真正有价值的经验收在 `01 知识` 里，按主题组织——一个主题一篇文档，而不是按「原则 / 方法 / 案例」这类抽象抽屉硬分，因为主题才是你回想知识时真实的线索。文档内部用章节和「一、二、三」编号的段落组织，一段记一条经验，把结论和它的来龙去脉写清楚。

这里有一条不动摇的规矩：你的原话怎么说，就怎么记。agent 不会替你润色、改写或压缩，因为原话里保留着你当时的思路和分寸，一旦被「整理」掉就找不回来了。如果它觉得有背景值得补充，会先征求你同意，再作为新的一段续在后面，而不是混进你的原话里。

结构上坚持「先长在一处，装不下了再分」。一个主题先都写在同一篇文档里，等某一章攒到大约 30 段、翻起来确实不便了，agent 才提议把这一章拆成独立文档、让原文档变成文件夹收留它们，绝不在内容还没长出来时就预先设计一堆层级。判断一个模块值不值得留也是同理：看它有没有真实的内容在流动，而不是看「以后说不定用得上」。

`02 摘录` 是唯一预置的示例模块，用来收诗词、名言、句子这类摘抄，初始化时会问你要不要开。开启后，长篇作品一篇一笔记，短句按类别聚合，某一类超过 100 条再自动拆开；不开也完全不影响使用，手册里会保留这一节，作为「模块规则该怎么写」的样子。

### 每一步都留痕，删错了也找得回

把知识库交给 agent，最怕的是它动了什么你却不知道。KnowOps 让每一笔改动都有账可查。`03 系统/日记` 下每天一篇日记，分「用户」和「agent」两章：agent 的动作按入库、沉淀、整理、归档、删除、补记、系统七类详细记录；你自己手动改过、没来得及记的，它会依据文件记录和 git 历史尽量帮你补记，并标明这是推断。每批改完，收件箱里还会放一份「待审阅」清单，写明动了什么、去哪看，你核对完删掉即可；根目录的看板则实时显示还有哪些待整理、最近更新了什么。

这背后是对 agent 角色的界定：它是管家，不是作者。它只负责格式整理、系统运营和按你明确的指令写入，不会自作主张决定「该记点什么」，也不会主动往你的文档里添东西。内容始终是你的，你也因此始终对库里有什么心里有数。

安全也不靠「它会小心」来保证，而是写成固定规矩：删除永远走系统回收站、随时能恢复；涉及大批文件或不可逆的改动，先把方案摆给你看、你点头了才动手；每次重要写入之后都会读回来核对一遍。另外，笔记默认会增量导出成不依赖 Obsidian 也能打开的 HTML，方便你在别的设备上阅读；你自己画的 canvas 白板则是完全的自由空间，不会被管理、检查或导出。

> 分工可以概括成一句话：**你**定义知识的结构与取舍，**skill** 提供职责、契约和安全边界，**agent** 据此完成整理与维护，**Obsidian** 把结果保存成可读、可链接、可恢复的笔记。

## 初始化之后，知识库长这样

```text
我的知识库/
├── 看板.md            # 库的正门：一屏总览（嵌入实时视图）
├── 00 收件箱/          # 一切随手记录的入口，平铺、没有子目录
├── 01 知识/            # 验证过的经验，按主题汇成文档
├── 03 系统/            # 库的设施：用户手册、日记、模板、看板数据
├── 04 归档/            # 不再活跃但保留的内容，按日期存放
└── .config/           # 隐藏目录：配置、变更记录、脚本、HTML 镜像
```

四个基础模块一句话就能记住：收件箱放「还没想清楚的」，知识放「验证过的」，系统放「库自己的痕迹和说明书」，归档放「不再活跃的」。`03 系统` 和 `04 归档` 固定排在最后两位，以后新增的模块一律插在它们前面顺延编号；根目录的 `看板.md` 是总览入口，不算模块。

初始化不会一次性造出一堆空文件夹：只先放好 `03 系统`（用户手册、模板）和根目录看板，收件箱、知识、归档都是第一次往里写东西时才出现。`.config/` 是隐藏的设施层，配置、变更历史、脚本和导出的 HTML 镜像都在这里，不占用你在 Obsidian 里的可见空间。

## 安装

按设备选择要装的 skill，**同一台设备不要同时装两个**：

| 设备 | 安装 |
|---|---|
| 桌面电脑（需要操作知识库） | `skills/knowops/` |
| 手机 / 平板等随身设备 | `skills/everywhere-note/` |

安装的本质都是「把 skill 目录复制到你所用 agent 的用户级 skill 目录」（具体位置因平台而异，一般形如 `~/.<平台>/skills/`，以该平台的安装说明为准）。获取方式任选其一：

- 从 [GitHub Releases](https://github.com/The-Daybreaker/KnowOps/releases) 下载 `<skill>-vX.Y.Z.zip`（每次发布自动生成，zip 内以 skill 名为根目录，解压即用）；
- 或克隆本仓库后自行复制：

```sh
git clone https://github.com/The-Daybreaker/KnowOps.git
# 再把 skills/ 下对应的 skill 目录复制到用户级 skill 目录
```

**Obsidian 的具体操作从哪来**：knowops 并不重复实现一套操作命令，笔记读写、Markdown、Bases、Canvas、网页提取这些具体能力交给 Obsidian 官方维护的工具 skill——obsidian-cli、obsidian-markdown、obsidian-bases、json-canvas、defuddle，它们来自 [kepano/obsidian-skills](https://github.com/kepano/obsidian-skills)，建议一并安装（见文末「相关项目」）。没装也不影响使用：knowops 会先和你确认，改用 Obsidian 官方帮助文档兜底，不会凭记忆猜命令。

## 上手

### 第一次使用：跑一遍初始化向导

桌面端的知识库任务会触发 knowops；发现这是个还没初始化的库，它会按顺序逐项和你确认，而不是一次性抛出所有问题：

1. vault 的实际路径与名称；
2. 四个基础模块与根目录看板（并说明扩展模块机制：今后你建文件夹、它来问规则）；
3. 是否启用「摘录」这个预置扩展模块；
4. 是否配置 GitHub 暂存库同步（可跳过）；
5. 扫描现有插件，逐个确认集成规则（比如「先提交版本、再云同步」），写进《用户手册》的「agent 约束」章；
6. 在 `03 系统/` 放好用户手册与笔记模板，引导你开启 Obsidian 核心插件 Templates 和 Daily notes；
7. 创建根目录看板，并按需开启 HTML 镜像导出。

所有配置写在库内隐藏目录 `.config/knowops.config.json`，一个 vault 一份。如果是一个已有内容的旧库，agent 不会自动迁移或改动，而是先和你现场商量怎么处理。

### 日常使用：直接用自然语言吩咐

| 你说 | agent 做 |
|---|---|
| 手机上：「记一下：……」 | everywhere-note 整理成规范笔记、当晚 22:00 提醒；配了暂存库且具备 GitHub 能力时一并上传 |
| 「入库今天手机记的」 | 优先收你直接给的内容；没给内容且配了暂存库时自动拉取新条目，序号命名写进 `00 收件箱`，并把暂存库里的源文件归档 |
| 「记一下：……」 | 写进 `00 收件箱/`，序号命名、补齐属性与标签 |
| 「摘录：将进酒，……」 | 按手册的摘录规则入库：长篇作品独立成篇，短句追加到对应分类 |
| 「这条经验入库，主题是架构设计」 | 合并进 `01 知识/` 对应主题文档的对应章节，原话完整保留 |
| 「审阅收件箱」 | 逐条定去向：归属模块 / 归档 / 删除 / 留下 |
| 「我建了个『读书』文件夹，以后书摘放这里」 | 问清该模块的规则 → 写进《用户手册》→ 此后照手册执行 |
| 「把这篇归档」 | 移入 `04 归档/当天日期/` |
| 「最近我都改了些什么」 | 翻日记与待审阅清单，给你一份操作脉络 |

### 让入库每天自动跑

希望电脑端定时把暂存库的新条目收进收件箱，可以用 `skills/automation-prompt-template.md`：把模板复制到支持定时或事件触发的 agent 平台，替换其中的 vault 路径、skill 位置和暂存库信息即可。它只做「检查暂存库 → 入库 → 归档源文件」这一件事，遇到拿不准的情况会停下汇报，不擅自决定。该模板随每次 Release 一并分发。

## 仓库结构

```text
KnowOps/
├── README.md / README.en.md / LICENSE / .gitignore / AGENTS.md
├── tools/                          # 开发期校验脚本（check.py，同时供 CI 使用）
├── .github/workflows/              # 推送 / PR 时自动跑核心校验
└── skills/
    ├── knowops/                    # 桌面端统一入口
    │   ├── SKILL.md                # 触发条件、加载规则、通用红线（主文件保持精简）
    │   ├── references/             # 业务细则，用到时才加载，避免规则互相干扰
    │   │   ├── workflow.md         # 业务流程：两道门、模块流转、日记、操作后流程
    │   │   ├── init-config.md      # 初始化向导、插件集成、配置与 HTML 导出
    │   │   ├── properties.md       # 属性、命名、目录与生命周期约定
    │   │   ├── redlines.md         # 执行层红线与直写例外
    │   │   └── desktop-ingest.md   # 暂存内容 / 暂存库拉取 → 收件箱
    │   ├── scripts/                # 随库分发的轻量脚本：html_export、vault_check
    │   └── assets/
    │       ├── system-manage/      # 库自身文档模板（用户手册、变更记录）
    │       ├── templates/          # 笔记模板（主题文档，供 Templates 插件使用）
    │       └── html-export.json    # HTML 导出范围配置
    ├── everywhere-note/            # 随身端捕获，单文件自洽
    │   └── SKILL.md
    └── automation-prompt-template.md  # 定时自动入库的提示词模板
```
