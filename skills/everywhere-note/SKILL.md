# everywhere-note 随身记录

## 定位

本 skill 用于手机/平板等移动或随身设备：用户调用（@/选中）本 skill 后直接口述
内容，生成符合知识库格式的 markdown 条目，并设置当晚 22:00 提醒。本 skill 单
文件自洽（只含本 SKILL.md），不依赖其他 skill；可选地，在用户指定暂存库且
平台具备 GitHub 能力时，把条目上传到 GitHub 暂存库，供电脑端自动入库。

## 触发方式

用户调用（@/选中）本 skill 后**直接口述内容**即可，例如“记一下：XX”；不需要
用户说明“入库”“备忘”“晚上处理”等词。记录类请求一律走本流程。

## 核心流程（3 步）

### 第 1 步：生成暂存条目

按下方的条目形状生成**一条独立、完整、可复制的 markdown**：

- 标题：`# 一句话标题`（标题直接写在文本开头，电脑端会用做文件名；
  **不带日期**——日期由 `created` 字段承载）；
- frontmatter：`type: capture` + `created`（ISO 8601，精确到分钟）+
  `tags`（**行内数组** `[a, b]`，避免传输中被换行破坏）；
- 可选字段：`source_url`（来自网页时）；
- 正文：**用户原话完整记录——不改写、不压缩**，怎么说的就怎么记；补充说明只
  按用户要求添加，不默默加；唯一例外：语音转文字的**明显错字**可顺手修正
  （为保住用户本意），但不脑补缺失信息；用户要求连错字都保留时以用户为准；
- 标题要能让人 3 秒看懂内容（摘录条目可用作品名或句子开头）；
- 内容明显是**待办**时：照实记录并在正文标注，同时提醒用户待办更适合放进
  专门的待办软件；不要试图在条目里安排任务流程。

完整形状（示例）：

```markdown
---
type: capture
created: 2026-08-10T14:30
tags: [灵感, 知识管理]
---

# 一句话标题

（用户原话，完整记录，可多行。）
```

摘录示例（用户口述“摘一句：天行健，君子以自强不息，周易里的。”）：

```markdown
---
type: capture
created: 2026-08-10T16:00
tags: [摘录]
---

# 天行健，君子以自强不息

> 天行健，君子以自强不息。
> —— 《周易》
```

### 第 2 步：输出

1. 先把完整 markdown 文本块展示给用户核对；
2. 若 agent **支持生成文件**：生成 `一句话标题.md`，保存到当前可用且用户
   可访问的位置（设备文件 / 备忘录 / agent 工作区等），保存后告知用户路径，
   并仍展示完整文本；
3. 若不支持生成文件：输出纯文本块供用户自行复制/保存。

**传输通道**：默认不做任何传输通道动作（不自动发送微信、邮件、云盘等）；唯一
例外是用户明确指定并确认的 GitHub 暂存库同步（见下）。未配置同步时，内容如何
到电脑由用户自行处理。

### 第 2.5 步：GitHub 暂存库同步（可选）

- **能力判断**：agent 自行判断平台是否具备 GitHub 能力（gh CLI / git / GitHub MCP
  等，任一可用即可）；不具备 → 跳过本步，维持本地输出。
- **配置来源**：暂存库配置（仓库 owner/repo、分支、目标知识库目录名）只存于
  对话上下文，同一对话内复用；**新对话重新询问**；用户可拒绝 → 跳过上传。
- **上传**：把本条目写入暂存库 `<目标知识库目录>/一句话标题.md`（文件名与
  本地条目一致）；本地是否另存文件不影响上传。
- **如实反馈**：上传成功 → 明确告知仓库与路径；失败 → 如实说明原因并保留本地
  条目，不假装已同步。
- **只上传本次条目**：仅上传本步生成的条目文件，不读取、不上传设备上其他内容，
  不泄露任何凭据。

### 第 3 步：设置入库提醒（默认 22:00）

- **规则**：仅当天确实产生了暂存条目时才设置提醒；当天没有记录不设置。
- **时间**：默认当晚 **22:00**，用户可指定其他时间。
- **合并**：同一天内多次记录只设一次提醒，提醒内容合并当天所有条目
  （逐条列出标题即可，不判断内容类型）。
- **已过 22:00**：记录时已过当天 22:00，提醒顺延至**次日 22:00** 并明确告知用户。
- **能力检查**：仅当平台确实支持提醒能力（系统提醒 / 日历 / IM / 定时任务等）
  时设置；**无法设置时如实告知**：“请记得 22:00 前把暂存内容发到电脑”，
  绝不假装已设置。

提醒内容模板（未同步）：

```
【知识库入库提醒】今天随身端暂存了 N 条内容：
- 标题 1
- 标题 2

回到电脑后，请把暂存内容发到电脑端 agent 并说“入库今天手机记的”。
```

已同步 GitHub 暂存库的条目，提醒结尾改为：

```
以上条目已同步 GitHub 暂存库。回到电脑后，说“入库”即可自动收入知识库。
```

## 补充格式要求

- 条目形状见第 1 步；文件名 / 首行标题：`一句话标题.md`，**不带日期**
  （日期由 `created` 承载）；
- 摘录条目可在正文标注出处（作者 / 来源），供电脑端沉淀时补全摘录笔记元数据；
- 条目去向由桌面端沉淀时按其知识库的规则判定，随身端不指定归属。

## 红线

1. **信息以用户给出为准**：内容、时间、归属不自行臆造；**用户原话完整记录，
   不改写、不压缩**；补充说明只按用户要求添加；缺关键信息时问一句。
2. **不做任何入库判断**：不判断内容类型、不标注用途字段、不指定去向——去向由
   桌面端沉淀时按其知识库规则判定；随身端不内嵌任何桌面库结构信息
   （编号/路径/归属/模块）。动机：桌面库结构与规则怎么演化（含跨 skill 版本
   差异），都不应迫使随身端发版或重装。
3. **不改动已有内容**：本 skill 不修改/删除知识库已有笔记。
4. **提醒不撒谎**：设置成功才说已设置；平台做不到时如实说明并给出手动替代。
5. **同步目标以用户指定为准**：只有用户明确指定了 GitHub 暂存库（仓库/分支/目标
   知识库目录）才上传；不猜测、不默认任何仓库。
6. **同步不撒谎**：上传成功/失败均如实告知；失败保留本地条目，不假装已同步；
   只上传本次生成的条目文件，不读取或上传其他内容与凭据。

## 契约说明（与 knowops 两端同步）

条目字段契约：`type` / `created` / `tags` / 标题（一句话标题，不带日期）。
修改字段时须同步更新 knowops 侧解析契约（`references/desktop-ingest.md`）。
GitHub 暂存库目录约定（`<知识库目录>/` 根目录放待入库条目、`归档/` 子目录放
已入库源文件）两端同步。旧版随身端生成的条目（含历史字段）桌面端宽容解析，
不拒收。
