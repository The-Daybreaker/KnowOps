# 知识库管理工作流规范（workflow.md）

> 本文件是 knowops 的流程规范（reference）：描述知识库应当如何组织、各模块的流程
> 应当怎么走，供用户与 agent 共同查阅。工具无关，任何执行方式均适用。
> 通用红线见 knowops SKILL.md；执行层红线见 references/redlines.md。
> 红线与流程冲突时：高风险操作（大规模影响文件、永久删除等）先征求同意；
> 低风险的流程内操作先执行，随后记录、告知用户并给出回退方案。
>
> 初始化、插件集成、配置与 HTML 导出见 `references/init-config.md`。

所有目录名与文件名规则均为**可配置默认值**（见 `.config/knowops.config.json`），
实际以用户确认的配置为准。

## 知识库模型

- **模块路由**：任何记录请求都应先判断内容类型与未来用途，再按「分类原则」
  路由；**简短、零碎、临时的顿悟/灵感/想法/不明确内容默认进入 00 收件箱**；
  明确完整的问题、日程、项目请求仍直达对应模块。
- **稳定核心 + 可插拔模块**：一级模块长期稳定；新增模块需满足"内容规模足够、
  有独立生命周期、有独立工作流"三个条件，编号顺延至归档与系统管理之前。
- **目录不承担全部导航**：文件夹只负责"放在哪里合理"；动态导航依靠标签、
  属性、双向链接、索引页与 Agent 智能整理。

## 模块总览（默认，可配置）

| 模块 | 职责 | 内部结构 |
|---|---|---|
| 00 收件箱 | 捕获入口：简短/零碎/临时内容 | 随手记 / 灵感 / 待整理内容 |
| 01 生活系统 | 发生什么 | 日记 / 日程 / 任务 / 问题 |
| 02 知识系统 | 理解了什么 | 概念原理 / 经验方法 / 方案 / 案例 |
| 03 资产系统 | 可以复用什么 | 模板 / 工作流 |
| 04 规范系统 | 应该遵守什么 | 原则 / 标准规范 / 检查清单 |
| 05 项目系统 | 正在创造什么 | 进行中 / 已完成 / 项目复盘 |
| 06 看板 | 一屏总览（数据库驱动） | 看板.md + 看板.base |
| 07 归档 | 不再活跃但保留的内容 | 按归档日期文件夹（如 2026年08月09日/） |
| 08 系统管理 | 知识库自身的用户文档 | 架构/分类/命名/Frontmatter/变更记录/用户手册 |

> **目录懒加载**：除 08 系统管理（初始化复制模板）与 06 看板（初始化默认创建）
> 外，其余模块目录在首次写入时自动创建；空文件夹在文件树中不显示。
>
> **移动目标目录**：把文件移动/归档到尚不存在的目录时，先创建目标目录再移动
> （懒加载目录不会自动出现，参考 07 归档的约定）。
>
> **编号规则**：一级目录全部带数字前缀；**归档与系统管理固定位于最后两位**，
> 未来新增模块插入它们之前并顺延编号。

## 分类原则（不问"哪个目录"，问"未来怎么用"）

1. **用于解释**（是什么/为什么）→ `02 知识系统/概念原理`
2. **用于指导行动**（应该怎么做/遵守什么）→ `04 规范系统`（应遵守）或
   `02 知识系统/经验方法`（个人做法）
3. **用于复制**（可复用的骨架/流程）→ `03 资产系统/模板` 或 `工作流`
4. **用于解决类似问题**（怎么解决一类问题）→ `02 知识系统/方案`
5. **只是参考**（真实发生过的事例）→ `02 知识系统/案例`

知识回答"这个东西是什么"，项目回答"我如何把它应用到现实"。

## 08 系统管理（用户文档）

- **内容**：`用户手册.md`（面向使用者）、`知识库架构.md`（模块图与设计原则）、
  `分类规则.md`（分类约定）、`记录规范.md`（命名与 Frontmatter）、
  `变更记录.md`（结构变更历史）——共 5 份**用户可见、可编辑**的文档。
- **来源**：初始化为本库创建全套文档（来源本 skill `assets/system-manage/`），
  **目标已存在则绝不覆盖**（询问后决定保留或合并）。
- **agent 读的个性化约束**（插件规则、额外红线、额外操作、旧库约定）统一存于
  `.config/agent-rules.md`，不在 08 系统管理；变更操作前读取（见 SKILL.md 红线 7）。
- **维护**：新增模块、结构变更时更新对应文档并写入 `变更记录.md` 与操作日志。

## 模块流程

### 00 收件箱（捕获入口）

- **捕获**：简短/零碎/临时的顿悟、灵感、想法、不明确内容默认写入：
  - `随手记/`：无明确类型的快速记录；
  - `灵感/`：顿悟、创意、新想法；
  - `待整理内容/`：URL 素材、草稿、未完成材料、暂时说不清的内容。
  命名与 frontmatter 见 `references/properties.md`（capture 条目）。
- **审阅维护**（用户发起为主，可配定时提醒）：逐条判断价值：
  1. 有价值且类型明确 → 按「分类原则」沉淀到目标模块（整理成正式笔记，
     原收件箱文件删除）；
  2. 有价值但暂不明确 → 留在 `待整理内容/`；
  3. 无价值 → 删除；
  4. 过时 → 归档到 `07 归档/<归档当日日期>/`。
- **沉淀去向**：知识/规范/资产/项目/问题/任务等按「分类原则」路由；沉淀时
  遵守目标模块的命名与属性规则，并建立双向链接。

### 01 生活系统（发生什么）

- **日记**：原生日记，按时间切分（默认 `日记/YYYY-MM/YYYY-MM-DD.md`）。
- **日程**：`日程/YYYY-MM-DD 标题.md`（属性见 `references/properties.md`）；
  完成/取消只改属性不移动；含时间信号时按平台自动化能力设置提醒并向用户确认。
- **任务**：任务文件夹内**每任务一篇笔记**（`任务/YYYY-MM-DD 任务标题.md`，
  属性见 `references/properties.md`），作为看板数据源；同时维护 `任务/TODO.md`
  人工快捷清单（`- [ ]` 未完成列表 +
  底部「已完成」折叠块）。**两边互为镜像、双向同步**：TODO.md 的新增/勾选/
  取消/删除会被识别并同步到任务笔记，任务笔记的改动也同步回 TODO.md；冲突
  无法判定时询问用户，不静默覆盖。**勾选/取消的位置同步**：勾选完成 → 将该行
  移入「已完成」折叠块，并同步任务笔记 `status: done` + `finished_date`；取消
  勾选 → 移回未完成列表，并同步任务笔记状态与完成时间。
- **问题**：`01 生活系统/问题/未解决|研究中|已解决|已沉淀/YYYY-MM-DD 简短描述.md`：
  - 未解决：已记录、未开始或搁置；
  - 研究中：正在主动学习/排查/推进；
  - 已解决：`status: done` + `resolved`（解决日期），TODO 同步勾选；
  - 已沉淀：沉淀知识笔记后原问题移入，`precipitated: true` + 双向链接，
    原问题长期保留，可再归档。

### 02 知识系统（理解了什么）

- 四类：`概念原理`（是什么/为什么）、`经验方法`（个人实践做法与技巧）、
  `方案`（针对一类问题的解决设计）、`案例`（真实发生过、可供参考）。
- 命名与 frontmatter 见 `references/properties.md`（knowledge 条目）。
- **二级目录按领域**（如 `概念原理/AI/`），领域同时写入 frontmatter `domain`；
  领域目录**用到才建**。
- **增长触发（仅知识系统）**：见 `references/properties.md`；建立领域二级目录
  前须用户确认。
- 相关知识之间互相链接，确保知识索引。

### 03 资产系统（可以复用什么）

- `模板/`：可复制骨架（项目模板、笔记模板等），文件不带日期前缀；
- `工作流/`：可重复执行的流程/脚本/自动化，脚本与工具归入此类；
- 附件仍不预设目录（位置以用户指令为准）。

### 04 规范系统（应该遵守什么）

- `原则/`：决定方向，高度抽象、长期稳定、适用范围广、不依赖具体工具；
- `标准规范/`：定义要求（命名要求、Frontmatter 要求、流程要求）；
- `检查清单/`：保证执行（发布前、归档前、收件箱审阅前等）；
- 文件不带日期前缀。

### 05 项目系统（正在创造什么）

- `进行中/<项目名>/`：项目默认包含 `项目说明.md`、`目标.md`、`决策记录.md`、
  `研究记录.md`、`问题.md`、`复盘.md`；
- 项目完成 → 整个项目文件夹移入 `已完成/`；
- 复盘 → 在 `项目复盘/` 建 `YYYY-MM-DD 项目名 复盘.md` 并链接回项目；
- 长期不活跃/结束项目可整体归档到 `07 归档/<日期>/<项目名>/`。

### 06 看板（数据库驱动）

- 形态：`看板.md`（嵌入容器）+ `看板.base`（views 数组承载各板块视图，
  每个视图各自过滤条件），**初始化默认创建**。
- 默认视图：收件箱-待整理、问题-未解决、问题-研究中、任务-未完成、
  日程-即将到来、项目-进行中、知识-最近沉淀。
- 可扩展：用户可随时要求新增/修改视图；模块首次出现内容时自动增补视图；
  日程一律 table 视图（不使用 calendar）。

### 07 归档

- 所有模块（收件箱、问题、项目等）都可归档；
- 文件夹按**归档当日日期**命名：`2026年08月09日/`（中文补零）；
- 单篇文件平铺；项目等文件夹整体归档时保留原文件夹名；
- **懒加载创建**：目录按需创建（空文件夹在文件树中不显示）；首次归档时先创建
  `07 归档/<归档日期>/`（目标目录不存在时先创建再写入/移入），归档后即可见；
- 归档动作记入操作日志与 `08 系统管理/变更记录.md`。

## 操作日志

- 位置：`<logDir>/<YYYY-MM>/<YYYY-MM-DD>.md`（默认 `.config/log/`，隐藏目录）；
- **写入/修改/移动/删除/归档后追加记录**（格式见「操作后流程」）；读取与搜索
  不记；日志不参与看板聚合与 HTML 导出。

## 操作后流程（每次写入 / 修改 / 移动 / 删除 / 归档后执行）

1. 写日志：在当日操作日志追加一行（`<时间> [类型] 动作与目标`）；
2. 任务双轨同步（涉及任务时）：更新任务笔记与 `TODO.md` 并保持一致；
3. 建立双向链接：沉淀/归档/相关笔记之间建立链接；
4. 插件规则：按 `.config/agent-rules.md` 中配置的规则执行（如版本提交、同步）；
5. HTML 镜像导出（若配置 `exportEnabled=true`）：写入/修改 → `html_export export-one`；
   删除/移动 → `html_export export`（含清理）；
6. 看板反映确认：看板已启用时确认实时反映正确；
7. 反馈：写入位置、建立的链接、后续建议。
