# 执行层红线与直写例外（knowops references）

> 执行任何 Obsidian 操作前先读本文件。通用红线见 SKILL.md；本文件只规定执行层
> 细节：变更分级、删除纪律、git、配置驱动、直写例外、回读校验、插件规则、安全边界。

## 变更分级与征求同意

大规模影响文件、永久删除等高风险变更前，先展示变更方案（源 → 目标、受影响的链接
与文件），征得用户同意后再执行；工作流程内规定的变更（如沉淀后删除原收件箱文件）
按流程执行；其余变更按风险判断，低风险先执行，随后记录、告知用户并给出回退方案；
含附件的笔记连同文件夹整体处理时一并说明。

## 删除纪律

- 只用工具的删除接口，**默认进系统回收站（可恢复）**；
- 严禁使用永久删除参数；严禁 `rm` / `Remove-Item` / `os.remove` 等绕过工具接口
  的删除方式；
- 告知用户"进回收站、可恢复"（流程内自动删除在执行后反馈中说明）。

## git

- vault 是 Git 仓库时，是否提交按 `Agent规则.md` 执行。

## 配置驱动

vault 名、目录名、文件位置一律以配置与用户确认为准；配置缺失时询问用户，不猜测。

## 直接文件访问例外清单

默认一律走工具接口；以下场景可直读直写文件，且**必须在回复中说明原因**：

| # | 场景 | 说明 |
|---|---|---|
| 1 | 工具不可用 | 工具未安装/应用未运行，且用户明确同意继续 |
| 2 | 格式校验 | 需对原始文件做 JSON / YAML / Canvas 结构校验 |
| 3 | 二进制附件导入 | 工具不支持二进制内容时直接复制文件 |
| 4 | 批量读取源文件 | 如 HTML 镜像导出：不依赖应用运行，需批量读源 |
| 5 | 超长内容 | 命令行参数可能被截断：工具先建占位文件，再直写完整内容 |
| 6 | 隐藏目录内文件 | 点开头目录（如 `.config/`）工具接口无法访问，可直写 |

## 重要写入后回读校验

读回核对内容与结构（见 SKILL.md 红线 6）；校验失败则修正后重写并重新校验。

## 插件规则

- 操作后按 `Agent规则.md` 中规则执行（如版本提交、同步；读取时机见 SKILL.md 红线 7）；
- 插件安装/卸载/规则变化先经用户确认，并更新该文件与 `变更记录.md`。

## 安全边界

- 知识库无关文件（配置/日志/脚本副本/导出产物）默认写入隐藏目录（如 `.config/`），
  不写入用户笔记内容区；
- `08 系统管理/` 规则文档为可见笔记，用户可编辑；
- 不对用户笔记做批量扫描式改写；修改前先看方案。
