# 执行层红线与直写例外（knowops references）

> 执行任何 Obsidian 操作前先读本文件。通用红线（变更分级、回读校验等）见 SKILL.md；
> 本文件只规定执行层细节：删除纪律、git、配置引导、环境就绪、工具纪律、直写例外、
> 插件规则、安全边界。

## 删除纪律

- 只用工具的删除接口，**默认进系统回收站（可恢复）**；
- 严禁使用永久删除参数；严禁 `rm` / `Remove-Item` / `os.remove` 等绕过工具接口
  的删除方式；
- 告知用户"进回收站、可恢复"（流程内自动删除在执行后反馈中说明）。

## git

- vault 是 Git 仓库时，是否提交按 `.config/agent-rules.md` 执行。

## 配置引导（每次操作前）

- 先确定目标 vault → 读取 `.config/knowops.config.json`（目录名/路径/导出偏好）与
  `.config/agent-rules.md`（若存在）；
- vault 名、目录名、文件位置一律以配置与用户确认为准；配置缺失时询问用户，不猜测；
- 找不到配置说明该 vault 尚未初始化，按 `references/init-config.md` 走初始化向导。

## 环境就绪

- Obsidian CLI 不可用或 Obsidian 未运行时，先拉起 Obsidian 再操作；拉起失败则
  提示用户手动打开，不静默继续。

## 工具纪律（官方 skill 优先）

- 任何 Obsidian CLI 命令或语法操作（读写改删、移动、日记、插件、Bases/Canvas/
  Markdown）执行前，先核对前置第 5 步记录的官方工具 skill 可用性；
- 对应 skill 已安装：**必须**加载该 skill 并以其语法与命令为准执行，不凭记忆
  猜测参数、不用 `--help` 试探、不以网络搜索结果替代；
- 对应 skill 未安装或不确定：先告知用户并确认兜底方式——安装官方 skill，或按
  官方文档 help.obsidian.md 执行；用户确认前不开始操作；
- 例外：用户明确同意自行探索（如「直接试试」）时按用户指示执行，但命令失败
  即回报请用户决策，不反复重试轰炸。

## 直接文件访问例外清单

默认一律走工具接口；以下场景可直读直写文件，且**必须在回复中说明原因**：

| # | 场景 | 说明 |
|---|---|---|
| 1 | 工具不可用 | 工具未安装/应用未运行，且用户明确同意继续 |
| 2 | 格式校验 | 需对原始文件做 JSON / YAML / Canvas 结构校验 |
| 3 | 二进制附件导入 | 工具不支持二进制内容时直接复制文件 |
| 4 | 批量读取源文件 | 如 HTML 镜像导出：不依赖应用运行，需批量读源 |
| 5 | 超长内容 | 命令行参数可能被截断：工具先建占位文件，再直写完整内容 |
| 6 | 隐藏目录内文件 | 点开头目录（如 `.config/`）工具接口无法访问，可直写 |

## 插件规则

- 插件集成规则存于 `.config/agent-rules.md`，操作后按其执行（如版本提交、同步）；
- 插件安装/卸载/规则变化先经用户确认，并更新 `.config/agent-rules.md`。

## 安全边界

- 知识库无关文件（配置/agent-rules/日志/脚本副本/导出产物）写入隐藏目录 `.config/`，
  不写入用户笔记内容区；
- `09 系统管理/` 为用户文档，可编辑；
- 不对用户笔记做批量扫描式改写；修改前先看方案。
