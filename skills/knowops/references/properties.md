# 属性、标签、命名与目录结构约定（knowops 领域设计）

> 本文档描述知识库的**领域设计**：属性含义、命名规范、目录模板、模块生命周期
> 与增长规则。属性的**写法**（frontmatter 语法）等具体形式不在本规范范围。
> 各约定的「规范层 / 配置层」归属见 `references/workflow.md`「规范与配置的边界」：
> 目录与偏好默认值属配置层（用户确认可改）；type 枚举语义与必填纪律属规范层
> （改动即破坏性变更）。

## 默认核心属性集（frontmatter）

| 属性 | 说明 | 取值/示例 |
|---|---|---|
| `type` | 笔记类型（六值） | `capture` / `knowledge` / `excerpt` / `daily` / `archive` / `system` |
| `capture_kind` | 捕获时的松提示（仅 capture） | `随手记` / `灵感` / `待整理内容` / `摘录`——只是捕获时的初步印象，**不作为路由依据**，沉淀去向由内容判定 |
| `excerpt_kind` | 摘录形态（仅 excerpt） | `长篇` / `短篇` |
| `category` | 摘录分类（仅 excerpt） | 长篇：`诗词` / `文言` / `文学` / `网络`；短篇：`名言` / `警句` / `思考` / `摘抄`（默认集合，可经确认扩展） |
| `author` | 作者（摘录长篇重点使用） | `李白` / `鲁迅` / `佚名` |
| `dynasty` | 朝代（仅摘录诗词/文言） | `唐` / `宋` / `先秦` |
| `source` / `source_url` | 来源 | 课程/文章/URL |
| `created` / `updated` | 创建/更新时间（**updated 每次修改必须更新，精确到分钟**） | `2026-08-10` / `2026-08-10T15:30` |
| `tags` | 标签（也可用行内 `#tag`） | `[fpga, 架构设计]` |
| `aliases` | 别名 | `[跨时钟域同步]` |

**必填与自由**（下表为权威定义，与 `scripts/vault_check.py` 的 REQUIRED 定义由
开发期 `tools/check.py` C6 兜底同步）：

| type | 必填属性（agent 写入时） |
|---|---|
| capture | `type` / `created` / `tags`（另带 `capture_kind` 松提示，不作必填） |
| knowledge | `type` / `created` / `updated` / `tags` |
| excerpt | `type` / `excerpt_kind` / `category` / `created` / `tags`；`excerpt_kind: 长篇` 另加 `source` |
| daily | `type`（其余从简，日记由 agent 自动维护） |
| system | `type` |

- 收件箱是校验豁免区：**用户手写无任何必填**，缺什么都在沉淀时补；
- 知识的属性载体是**主题文档**——主题文档内的条目是章节小节，不带独立属性；
- 摘录长篇的 `source`（出处）未知填 `佚名` 或留空待补；
- 除上表外，其余属性用户可自由增删；`updated` 在修改时必须更新。

## 标签与双向链接约定

- **积极打标签**：创建笔记时根据内容主动打层级标签，如 `#领域/fpga`、
  `#摘录/诗词`、`#架构设计`；
- 标签、属性与双向链接是看板聚合与检索的基础；
- **双向链接**：沉淀/归档/相关笔记之间建立链接；发现相关内容时主动补链。

## 命名规范（默认）

| 内容 | 命名 | 说明 |
|---|---|---|
| 一级目录 | `00 收件箱` / `01 知识` / `02 摘录` / `03 系统` / `04 归档` | 全部带数字前缀；系统、归档固定末两位 |
| 二级目录 | `日记` / `模板` / `长篇` / `短篇` 等 | 不带数字前缀 |
| 收件箱文件 | `序号-内容简述.md` | 序号＝现有最大序号＋1，两位补零，超 99 三位；平铺无子目录 |
| 知识主题文档 | `主题名.md` | 名字自解释；不自解释的标题下一行补使用场景 |
| 摘录长篇笔记 | `作品名.md` | 稳定名称利于链接引用；同名不同作者：`作品名 作者.md`（作品名始终在前） |
| 摘录短篇聚合 | `名言.md` 等分类名 | 超量拆分后：`<分类>/<分类> 01.md` 起序号递增 |
| 日记 | `03 系统/日记/YYYY/YYYY-MM-DD.md` | 按年切分 |
| 归档文件夹 | `2026年08月09日/` | 中文补零日期（归档当日） |
| 看板 | 根目录 `看板.md` ＋ `03 系统/看板.base` | 看板不是模块，不参与编号 |

## 默认目录模板（首次初始化时展示，用户确认后写入配置）

```
<vault>/.config/                     ← 隐藏目录：机器配置/agent-rules/脚本/导出
├── knowops.config.json            # 配置（schema 版本 = skill 版本）
├── agent-rules.md                 # agent 读的个性化约束（插件规则等）
├── scripts/                       # html_export.py + html-export.json + vault_check.py
└── HTML-Export/                   # HTML 镜像导出（默认组件）

<Obsidian Vault>/
├── 看板.md                        # 库的正门：一屏总览（嵌入 03 系统/看板.base）
├── 00 收件箱/                     # 平铺：序号-内容简述.md（宽进严出，校验豁免）
├── 01 知识/                       # 主题文档（起步一份通用示例）
│   └── 示例主题.md
├── 02 摘录/
│   ├── 长篇/                      # 作品名.md（分类文件夹用到才建：诗词/文言/文学/网络）
│   └── 短篇/                      # 名言.md / 警句.md / 思考.md / 摘抄.md（超100条拆分）
├── 03 系统/
│   ├── 日记/                      # YYYY/YYYY-MM-DD.md（按年切分，操作记录）
│   ├── 模板/                      # 主题文档模板 / 摘录长篇模板
│   ├── 看板.base
│   ├── 用户手册.md
│   └── 变更记录.md
└── 04 归档/
    └── 2026年08月09日/
```

> 约定要点：
> - 知识库无关文件（配置/脚本/HTML 导出）默认放 `.config/` 隐藏目录；操作记录
>   （日记）在 `03 系统/日记/`，用户可见可翻；
> - URL/网页素材作为捕获内容进入 `00 收件箱`；
> - 附件不预设目录（位置以用户指令为准）；
> - 用户自建的白板（`.canvas`）等非笔记文件不管理、不校验、不导出；
> - **懒加载**：初始化预置 03 系统（用户文档、模板）与 01 知识（示例主题文档），
>   并创建根目录看板；其余模块首次写入时自动创建；空文件夹在文件树中不显示。

## 模块生命周期

- **收件箱**：捕获（agent 写入带属性 / 用户手写零要求）→ 审阅沉淀（摘抄→02 摘录；
  经验结论→01 知识主题文档；不再活跃→04 归档；无价值→删除；不明确→留下，
  原文件保留；已离箱条目的原收件箱文件在沉淀后删除）。
- **知识**：条目合并进主题文档（章节不存在则新增；主题文档不存在则新建）→
  单章约 30 条涨破 → 提议拆分为文件夹（用户同意后执行）。
- **摘录**：长篇一篇作品一篇笔记（命名 `作品名.md`）；短篇按分类聚合追加
  （超 100 条拆分序号文件）；分类在摘录时判定（拿不准询问用户）。
- **归档**：`04 归档/<归档当日日期>/`，所有模块均可归档，动作记入变更记录。
- **系统**：日记由操作自动追加；模板随初始化复制（已存在不覆盖）；用户文档
  初始化复制、随结构变更维护；新模块建立时看板同步增补视图。

## 增长规则（先单体、涨破再拆）

- **知识主题文档**：单章条目超过约 **30 条**时，提议把该章拆成独立文档，原文档
  升级为同名文件夹收留（主文档保留其余章节，顶部列拆出文档链接）。拆分须用户
  确认。**不提前设计层级**——这是全库唯一的生长方式。
- **摘录短篇**：单分类超 **100 条**拆分（机制见 `references/workflow.md`）。

## 配置键说明（preferences 默认值）

| 键 | 默认值 | 说明 |
|---|---|---|
| `inboxDir` | `00 收件箱` | 收件箱模块 |
| `knowledgeDir` | `01 知识` | 知识模块 |
| `excerptDir` | `02 摘录` | 摘录模块 |
| `systemDir` | `03 系统` | 系统模块 |
| `archiveDir` | `04 归档` | 归档模块 |
| `dailyFolder` | `03 系统/日记` | 日记（＝操作记录）目录 |
| `dailyFormat` | `YYYY/YYYY-MM-DD` | 日记日期格式（按年切分） |
| `templatesDir` | `03 系统/模板` | 笔记模板目录 |

配置为 `.config/knowops.config.json`（单 vault，agent 直接读写）；顶层键包括
`version`（跟随 skill 版本）、`vaultPath`、`exportRoot`（默认 `.config/HTML-Export`）、
`exportEnabled`（默认 true）、`preferences`（上表）。修改需用户知情后进行；
不兼容旧版本配置，旧库接入时现场询问用户。

> 看板位置固定（根目录 `看板.md` ＋ `03 系统/看板.base`），不设配置键——
> 固定即简单，少一个可漂移的旋钮。

- **GitHub 暂存库同步（可选顶层键 `githubSync`）**：`enabled`（bool，默认 false）/
  `repo`（owner/repo）/ `branch`（默认 main）/ `folder`（本库在暂存库中的目录名，
  默认 = vault 文件夹名）；缺失或 `enabled=false` 视为未启用。暂存库约定：根目录下
  每个知识库一个目录；`<folder>/` 根目录放待入库条目（everywhere-note 上传位置），
  `<folder>/归档/<YYYY年MM月DD日>/` 放已入库源文件（按入库当天日期切分，中文补零；
  本地归档不重复存放）。
