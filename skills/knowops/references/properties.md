# 属性、标签、命名与目录结构约定（knowops 领域设计，均为可配置默认值）

> 本文档描述知识库的**领域设计**：属性含义、命名规范、目录模板、模块生命周期
> 与增长触发规则。属性的**写法**（frontmatter 语法）等具体形式不在本规范范围。

## 默认核心属性集（frontmatter）

| 属性 | 说明 | 取值/示例 |
|---|---|---|
| `type` | 笔记类型 | `capture` / `question` / `knowledge` / `principle` / `standard` / `checklist` / `template` / `workflow` / `project` / `daily` / `event` / `task` / `review` / `archive` / `system` |
| `capture_kind` | 收件箱子类（仅 capture） | `随手记` / `灵感` / `待整理内容` |
| `knowledge_type` | 知识类型（仅 knowledge） | `概念原理` / `经验方法` / `方案` / `案例` |
| `domain` | 领域（知识系统重点使用） | `AI` / `知识管理` / `fpga` |
| `status` | 状态 | 问题：`pending`/`in-progress`/`done`；任务：`pending`/`done`；日程：`scheduled`/`done`/`cancelled`；项目：`active`/`completed`；收件箱：`pending`（待整理） |
| `precipitated` | 问题已沉淀标记（仅已沉淀） | `true` 或沉淀日期 |
| `source` / `source_url` | 来源 | 课程/文章/URL |
| `created` / `updated` | 创建/更新时间（**updated 每次修改必须更新，精确到分钟**） | `2026-08-10` / `2026-08-10T15:30` |
| `resolved` | 问题解决日期 / 知识沉淀日期 | `2026-08-15` |
| `due` / `finished_date` | 任务截止 / 完成时间 | `2026-08-10` |
| `date` / `end` / `location` | 日程开始/结束/地点（仅日程，ISO 格式） | `2026-08-07T15:00` / `2026-08-07T16:30` / 会议室A |
| `project` | 项目归属（项目相关笔记） | `[[项目名]]` 或项目名 |
| `tags` | 标签（也可用行内 `#tag`） | `[领域/ai, 知识/概念原理]` |
| `aliases` | 别名 | `[异步复位问题记录]` |

**必填与自由**：除各模块明确要求的必填属性（capture 至少 `type`/`capture_kind`/
`created`/标签；knowledge 至少 `type`/`knowledge_type`/`domain`/`created`/`source`）
外，其余属性用户可自由增删；`updated` 在修改时必须更新。

## 标签与双向链接约定

- **积极打标签**：创建笔记时根据内容主动打层级标签，如 `#领域/ai`、
  `#知识/概念原理`、`#项目/xxx`、`#日程`；
- 状态类信息优先用 `status` 属性（便于聚合过滤），状态标签不强制；
- **双向链接**：沉淀/归档/相关知识/任务与 TODO 之间建立链接；发现相关内容时
  主动补链；
- 标签、属性与双向链接是看板聚合与检索的基础。

## 命名规范（默认）

| 内容 | 命名 | 说明 |
|---|---|---|
| 一级目录 | `00 收件箱` … `08 系统管理` | 全部带数字前缀；归档与系统管理固定最后两位 |
| 二级目录 | `随手记` / `日记` / `概念原理` 等 | 不带数字前缀 |
| 收件箱/问题/知识/日程/复盘文件 | `YYYY-MM-DD 标题.md` | 日期前缀利于检索与排序 |
| 规范/资产文件 | `标题.md` | 可复用物用稳定名称，不带日期前缀 |
| 任务笔记 | `YYYY-MM-DD 任务标题.md` | 位于 `01 生活系统/任务/` |
| 项目文件夹 | `<项目名>/` | 位于进行中/已完成下；复盘 `YYYY-MM-DD 项目名 复盘.md` |
| 归档文件夹 | `2026年08月09日/` | 中文补零日期（归档当日） |
| 看板 | `看板.md` + `看板.base` | 位于 `06 看板/` |

> 约定要点：
> - 知识库无关文件（配置/日志/脚本/HTML 导出）默认放 `.config/` 隐藏目录；
> - 剪藏取消为独立模块：URL/网页素材作为捕获内容进入 `00 收件箱/待整理内容`；
> - 附件不预设目录（位置以用户指令为准）；
> - 知识系统二级目录按领域，**用到才建**，目录最多三层为知识系统内部的软性
>   建议；
> - **模块目录懒加载**：空文件夹在文件树中不显示；初始化只预置 08 系统管理 与
>   06 看板，其余模块首次写入时自动创建（07 归档 在首次归档时创建日期文件夹）。

## 模块生命周期

- **收件箱**：捕获（`type: capture` + `capture_kind`）→ 审阅 → 沉淀（删除原
  记录）/ 保留待整理 / 删除 / 归档。
- **问题**：未解决（pending）→ 研究中（in-progress）→ 已解决（done +
  resolved）→ 已沉淀（precipitated + 知识笔记双向链接，原问题保留）。
- **知识**：`知识系统/<类型>/YYYY-MM-DD 标题.md`；属性 `type: knowledge` +
  `knowledge_type` + `domain`；类型与领域在沉淀时判定（新增需经确认）。
- **任务**：任务笔记为数据源（`type: task` + `status` + `due`），TODO.md 为
  人工快捷清单，双向同步；完成项进「已完成」折叠块。
- **日程**：`type: event` + `date`/`end`/`location`/`status` + 「日程」标签；
  完成/取消只改属性不移动。
- **项目**：进行中 → 已完成（整体移动）→ 复盘（`项目复盘/`）→ 可归档。
- **归档**：`07 归档/<归档当日日期>/`，所有模块均可归档，动作记入变更记录。
- **系统管理**：初始化由 skill 模板复制，后续以本库实际记录为准并持续维护。

## 知识系统增长触发规则

- 同一目录 <50 篇：不拆，保持平铺；
- 接近或达到 50 篇且同 `domain` 集中：向用户**建议**创建领域二级目录（如
  `概念原理/AI/`），**用户确认后**执行，并创建 `<领域>索引.md`（如
  `AI索引.md`）；
- >150 篇：评估是否建立三级目录（谨慎，不提前设计）。

|---|---|---|
| `inboxDir` | `00 收件箱` | 收件箱模块 |
| `lifeDir` | `01 生活系统` | 生活系统模块 |
| `knowledgeDir` | `02 知识系统` | 知识系统模块 |
| `assetsDir` | `03 资产系统` | 资产系统模块 |
| `standardsDir` | `04 规范系统` | 规范系统模块 |
| `projectsDir` | `05 项目系统` | 项目系统模块 |
| `dashboardDir` | `06 看板` | 看板模块 |
| `archiveDir` | `07 归档` | 归档模块 |
| `systemDir` | `08 系统管理` | 系统管理模块 |
| `dailyFolder` | `01 生活系统/日记` | 原生日记目录 |
| `dailyFormat` | `YYYY-MM/YYYY-MM-DD` | 日记日期格式 |
| `scheduleDir` | `01 生活系统/日程` | 日程目录 |
| `questionDir` | `01 生活系统/问题` | 问题目录 |
| `todoDir` | `01 生活系统/任务` | 任务目录 |
| `todoFile` | `01 生活系统/任务/TODO.md` | 人工快捷清单文件 |
| `logDir` | `.config/log` | 操作日志目录 |
| `configDir` | `config` | 隐藏目录名存储值（不带点；脚本自动补前缀，实际目录 `.config`） |
| `exportDirName` | `HTML-Export` | HTML 导出子目录名 |
| `dashboardFile` | `看板.md` | 看板嵌入容器文件名 |

配置键见 `kb_config.py list` 输出的 `preferences`；修改用
`kb_config.py set preferences.<键> <值>`（用户知情后进行）。配置 schema 版本
跟随 skill 版本；不兼容旧版本配置，其他旧库接入
时现场询问用户。

> 配置文件名：`knowops.config.json`（默认 `.config/`）。
