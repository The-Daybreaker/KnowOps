# 属性、标签、命名与配置约定（knowops 领域设计）

> 本文档描述知识库的**基础领域设计**：属性含义、命名规范、目录骨架、模块
> 生命周期与配置键。属性的**写法**（frontmatter 语法）等具体形式不在本规范范围。
> 各约定的「规范层 / 配置层 / 库内本体」归属见 `references/workflow.md`
> 「规范与配置的边界」。
>
> **业务模块的专属属性、分类集合与命名约定由用户手册「模块规则」章节定义**
> （如摘录的 excerpt_kind / category / author / dynasty 及其分类清单），
> 本文件只定义基础属性与机制。

## 默认核心属性集（frontmatter）

| 属性 | 说明 | 取值/示例 |
|---|---|---|
| `type` | 笔记类型——基础值五枚举；**扩展模块的 type 值随模块登记**（config `preferences.modules[].type`，规则见用户手册） | `capture` / `knowledge` / `daily` / `archive` / `system` |
| `source` / `source_url` | 来源 | 课程/文章/URL |
| `created` / `updated` | 创建/更新时间（**updated 每次修改必须更新，精确到分钟**） | `2026-08-10` / `2026-08-10T15:30` |
| `tags` | 标签（也可用行内 `#tag`） | `[fpga, 架构设计]` |
| `aliases` | 别名 | `[跨时钟域同步]` |

**必填与自由**（下表为权威定义，与 `scripts/vault_check.py` 的 REQUIRED 定义
须保持同步（改动两端同步）；扩展模块的必填属性由手册该模块节定义，
脚本对已登记模块只做 type 存在性校验）：

| type | 必填属性（agent 写入时） |
|---|---|
| capture | `type` / `created` / `tags` |
| knowledge | `type` / `created` / `updated` / `tags` |
| daily | `type`（其余从简，日记由 agent 自动维护） |
| archive | `type`（归档移动时由 agent 标注） |
| system | `type` |

**校验口径**：基础枚举硬校验（不通过即报错）；已登记模块按登记的 type 校验
（config `preferences.modules[].type`）；未登记目录/type 只出 warning 不判失败。

- 收件箱是校验豁免区：**用户手写无任何必填**，缺什么都在沉淀时补；
- 知识的属性载体是**主题文档**——主题文档内的条目是章节小节，不带独立属性；
- 除上表外，其余属性用户可自由增删；`updated` 在修改时必须更新。

## 标签与双向链接约定

- **积极打标签**：创建笔记时根据内容主动打层级标签，如 `#领域/fpga`、
  `#架构设计`；
- 标签、属性与双向链接是看板聚合与检索的基础；
- **双向链接**：沉淀/归档/相关笔记之间建立链接；发现相关内容时主动补链。

## 命名规范（基础）

| 内容 | 命名 | 说明 |
|---|---|---|
| 一级目录 | `NN 名称`（如 `00 收件箱`） | 全部带数字前缀；系统、归档固定末两位；扩展模块登记时顺延编号，名称以手册登记为准 |
| 二级目录 | `日记` / `模板` 等 | 不带数字前缀；扩展模块的二级结构按手册该模块节 |
| 收件箱文件 | `序号-内容简述.md` | 序号＝现有**`数字-` 开头 md 文件**的最大序号＋1，两位补零，超 99 三位；平铺无子目录；`待审阅-YYYY-MM-DD.md` 与用户手写文件不计入序号 |
| 知识主题文档 | `主题名.md` | 名字自解释；不自解释的标题下一行补使用场景 |
| 日记 | `03 系统/日记/YYYY/YYYY-MM-DD.md` | 按 Obsidian Daily notes 规则（位置与日期格式按插件设置） |
| 归档文件夹 | `2026年08月09日/` | 中文补零日期（归档当日） |
| 待审阅文件 | `待审阅-YYYY-MM-DD.md`（收件箱内） | agent 写入审计用运营件，不带序号 |
| 看板 | 根目录 `看板.md` ＋ `03 系统/看板.base` | 看板不是模块，不参与编号 |
| 扩展模块内部 | —— | 按用户手册该模块节（登记时确认） |

## 默认目录骨架（基础，首次初始化时展示，用户确认后写入配置）

```
<vault>/.config/                     ← 隐藏目录：机器配置/agent-rules/变更记录/脚本/导出
├── knowops.config.json            # 配置（schema 版本 = skill 版本）
├── agent-rules.md                 # agent 读的个性化约束（插件规则等）
├── 变更记录.md                    # 库结构与规则变更史（agent 维护，人可查看）
├── scripts/                       # html_export.py + html-export.json + vault_check.py
└── HTML-Export/                   # HTML 镜像导出（默认组件）

<Obsidian Vault>/
├── 看板.md                        # 库的正门：一屏总览（嵌入 03 系统/看板.base）
├── 00 收件箱/                     # 平铺：序号-内容简述.md（宽进严出，校验豁免；含待审阅文件）
├── 01 知识/                       # 主题文档（起步为空，首次写入自动出现）
├── 03 系统/
│   ├── 日记/                      # Daily notes：YYYY/YYYY-MM-DD.md（两章节操作记录）
│   ├── 模板/                      # 主题文档模板
│   ├── 看板.base
│   └── 用户手册.md                # 模块规则（唯一事实来源）+ 使用说明
├── 04 归档/
│   └── 2026年08月09日/
└── <NN 扩展模块>/                 # 用户自建并登记（如 02 摘录），规则见用户手册
```

> 约定要点：
> - 知识库无关文件（配置/agent 约束/变更记录/脚本/HTML 导出）默认放 `.config/`
>   隐藏目录；操作记录（日记）在 `03 系统/日记/`，用户可见可翻；
> - URL/网页素材作为捕获内容进入 `00 收件箱`；
> - 附件不预设目录（位置以用户指令为准）；
> - 用户自建的白板（`.canvas`）等非笔记文件不管理、不校验、不导出；
> - **懒加载**：初始化预置 03 系统（用户手册、模板）并创建根目录看板；
>   01 知识、收件箱、归档首次写入时自动创建；空文件夹在文件树中不显示；
> - **新增模块**：用户在库里新建文件夹 → agent 问规则 → 写进用户手册
>   （见 `references/workflow.md`「模块发现与登记」）。

## 模块生命周期

- **收件箱**：捕获（agent 写入带属性 / 用户手写零要求）→ 审阅沉淀（按手册
  判定归属模块；不再活跃→04 归档；无价值→删除；不明确→留下，原文件保留；
  已离箱条目的原收件箱文件在沉淀后删除）。
- **知识**：条目合并进主题文档（章节不存在则新增；主题文档不存在则新建；
  正文＝用户原话完整＋可选补充）→ 单章约 30 条涨破 → 提议拆分为文件夹
  （用户同意后执行）。
- **扩展模块**：登记（手册模块节 + config modules + 看板视图 + 编号）→ 按
  手册该节规则使用 → 目录消失时注销问询（手册节删除/标注停用由用户定）。
- **归档**：`04 归档/<归档当日日期>/`，所有模块均可归档，动作记入日记；
  结构性调整另记 `.config/变更记录.md`。
- **系统**：日记由操作自动追加（两章节）；模板随初始化复制（已存在不覆盖）；
  用户手册初始化复制、随结构变更维护（agent 必读的规则来源）；结构与规则
  变更史记入 `.config/变更记录.md`；模块登记/注销时看板同步增补/移除视图。

## 增长规则（先单体、涨破再拆）

- **知识主题文档**：单章条目超过约 **30 条**时，提议把该章拆成独立文档，原文档
  升级为同名文件夹收留（主文档保留其余章节，顶部列拆出文档链接）。拆分须用户
  确认。**不提前设计层级**。
- **其他模块**：内部的聚合与拆分阈值（如摘录短篇「超 100 条拆分」）是该模块
  规则的一部分，登记时确认、写在手册模块节里，skill 不写死。

## 配置键说明（preferences）

| 键 | 默认值 | 说明 |
|---|---|---|
| `modules` | 基础四模块（见下） | 模块登记清单（机器索引）：`[{ dir, name, type, base }]`——dir＝一级目录全名（含编号）、name＝模块名、type＝该模块笔记的 type 值、base＝是否基础模块；**在列即已登记**；规则正文在用户手册 |
| `dailyFolder` | `03 系统/日记` | 日记（＝操作记录）目录 |
| `dailyFormat` | `YYYY/YYYY-MM-DD` | 日记日期格式（按 Obsidian Daily notes，年切分） |
| `templatesDir` | `03 系统/模板` | 笔记模板目录 |

`modules` 默认值（基础四模块；摘录等扩展模块启用登记后追加）：

```json
[
  { "dir": "00 收件箱", "name": "收件箱", "type": "capture",  "base": true },
  { "dir": "01 知识",   "name": "知识",   "type": "knowledge", "base": true },
  { "dir": "03 系统",   "name": "系统",   "type": "system",   "base": true },
  { "dir": "04 归档",   "name": "归档",   "type": "archive",  "base": true }
]
```

配置为 `.config/knowops.config.json`（单 vault，agent 直接读写）；顶层键包括
`version`（跟随 skill 版本）、`vaultPath`、`exportRoot`（默认 `.config/HTML-Export`）、
`exportEnabled`（默认 true）、`preferences`（上表）。修改需用户知情后进行；
不兼容旧版本配置，旧库接入时现场询问用户。

> 看板位置固定（根目录 `看板.md` ＋ `03 系统/看板.base`），不设配置键——
> 固定即简单，少一个可漂移的旋钮。

- **GitHub 暂存库同步（可选顶层键 `githubSync`）**：`enabled`（bool，默认 false）/
  `repo`（owner/repo）/ `branch`（默认 main）/ `folder`（本库在暂存库中的
  目录名，默认 = vault 文件夹名）；缺失或 `enabled=false` 视为未启用。暂存库约定：
  根目录下每个知识库一个目录；`<folder>/` 根目录放待入库条目（everywhere-note
  上传位置），`<folder>/归档/<YYYY年MM月DD日>/` 放已入库源文件（按入库当天日期
  切分，中文补零；本地归档不重复存放）。
