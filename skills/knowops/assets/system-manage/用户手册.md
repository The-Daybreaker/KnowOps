# 知识库 · 用户手册

> 本手册在首次初始化时由 AI agent 创建，是这个知识库的总说明书：它是什么、
> 每个模块装什么、怎么记、怎么整理、怎么找。可以随手修改——它就是给你看的。
> **第二章「模块规则」与第八章「agent 约束」同时是 agent 的执行依据**：
> agent 入库、分类、整理、操作时按这两章执行；你改了规则，agent 就按新
> 规则来。重复初始化不会覆盖本手册。

## 一、这是个什么知识库

这个知识库存的是**一页纸能写完的东西**：摘抄下来的好句子、验证过确实管用的
经验、还没想清楚但值得先留下的念头。

它**不收**在别处有更合适去处的东西：

- 待办事项——待办软件更擅长催你和打勾；
- 项目文件——它们应该和项目放在一起，放进知识库反而要两边同步，还会过时；
- 可以执行的脚本、项目模板这类东西——它们住在自己所属的仓库里。

为什么这么划？因为一样东西如果在别处有家，知识库里的副本就成了影子：你要花
力气保持两边一致，稍不留神库里那份就过时了，反而骗人。所以这个库只收「没有
更具体去处」的内容——这是它保持轻、保持可信的根本原因。

库由 **Obsidian + AI agent** 共同维护：你在 Obsidian 里自由地写和看；agent
在对话里帮你记录、整理、补全格式。这里有一条贯穿始终的约定——**宽进严出**：

- **宽进**：你往库里放东西没有任何门槛。格式、命名、分类都不是你的义务；
- **严出**：所有规范由 agent 执行。内容要正式沉淀时，agent 会把缺的补齐、
  把不合规范的整理好。

换句话说：规则是约束 agent 的，不是拦住你的。

## 二、模块规则

打开文件树，你会看到编号的模块文件夹（有些暂时看不到，空文件夹不显示——
第一次往里写东西时才出现，不是怪事）：

| 位置 | 装什么 | 一句话记住 |
|---|---|---|
| 根目录 `看板.md` | 一屏总览：收件箱待沉淀、最近更新 | 库的正门 |
| `00 收件箱/` | 没想清楚、来不及整理的 | 先丢这里 |
| `01 知识/` | 验证过的经验与结论 | 确认管用的 |
| `02 摘录/` | 抄来收藏的诗词、名言、句子（未启用则无此目录，下节保留作示例） | 抄来的 |
| `03 系统/` | 库自己的痕迹和说明书（日记、模板、本手册） | 库的后台 |
| `04 归档/` | 不再活跃但舍不得删的 | 冷存储 |

编号规则：系统、归档永远排最后两位（归档殿后），新模块插在它们前面顺延
编号。`02 摘录` 是**预置的第一个扩展模块**——它和以后你自己加的模块一样，
规则都登记在本章里；不想用它，删掉文件夹即可（agent 会来问你要不要把规则
一并向你确认处理）。

**怎么加新模块**：直接在库里新建一个文件夹，然后告诉 agent「这是XX模块」。
agent 会来问你几件事（装什么、什么内容进、内部怎么分、怎么命名），把答案
写进本章，之后它就按这套规则帮你入库和分类。

### 00 收件箱

- **职责**：捕获入口——没想清楚的、来不及整理的，先放这里。
- **入库规则**：简短、零碎、临时、说不清的内容都进这里；agent 写入的每条
  都带序号和属性；你手写不加任何格式；内容沉淀时逐条判定去向。
- **分类规则**：平铺，无子目录，不分类。
- **命名约定**：agent 写入用 `序号-内容简述.md`（序号接着现有最大序号＋1）；
  你手写随意起名。`待审阅-YYYY-MM-DD.md` 是 agent 留给你的审阅清单（见第四章），
  不是内容条目。

### 01 知识

- **职责**：跨项目验证过的经验与结论，以及你主动收录的理解类内容。
- **入库规则**：一条经验/结论 → 合并进对应主题文档的对应章节（章节没有就
  加章节，主题文档没有就新建）；写入前 agent 会查相似，疑似重复时问你。
- **分类规则**：按主题组织，一个主题一份文档，不按用途分类；条目按章节
  组织；单章超过约 30 条时 agent 会提议拆分（先单体、涨破再拆）。
- **命名约定**：主题文档 `主题名.md`，名字自解释；不自解释的在标题下补
  一行使用场景。
- **条目写法**：条目标题是一句可直接执行的结论；**正文完整保留你的原话**
  （agent 不改写、不压缩你说的话），需要背景说明时另起「补充」小节——
  也只在你要求或同意后才写。

### 02 摘录（第一个示例扩展模块）

- **职责**：抄来收藏的——外部摘抄（诗词、文言、名言警句等）与你已成型的
  单句感悟；未成型的想法（灵感）不进这里，走收件箱。
- **入库规则**：长篇作品一篇作品一篇笔记；短句追加到对应分类聚合文件末尾；
  写入前查相似，疑似重复时问你；「感想」小节只在你明确要求时写，agent 不代写。
- **分类规则**：
  - `长篇/`：诗词、文言等有完整篇幅的作品；分类文件夹（诗词 / 文言 / 文学 /
    网络）用到才建，可扩展（新增分类经你确认）；
  - `短篇/`：名言 / 警句 / 思考 / 摘抄 四类聚合（名言＝名人名言有明确作者；
    警句＝警示格言作者常不详；思考＝你自己的单句感悟；摘抄＝其他短句兜底）；
    可经你确认扩展；
  - 超量拆分：短篇任一分类超过 100 条，该分类由文件变为文件夹，继续顺延
    新开序号文件。
- **命名约定**：长篇用 `作品名.md`（同名不同作者用 `作品名 作者.md`）；短篇
  聚合文件用分类名命名。
- **属性**：长篇记 `excerpt_kind: 长篇`、`category`、`author`、`source`（未知
  填佚名），诗词文言可加 `dynasty`；短篇记 `excerpt_kind: 短篇`、`category`。

### 03 系统

- **职责**：库自己的痕迹和说明书。
- **入库规则**：不由用户放入内容；日记由 agent 自动维护，模板和本手册随
  初始化创建。
- **分类规则**：`日记/`（操作记录，按年分文件夹）、`模板/`（Obsidian 模板）、
  `看板.base`（看板数据）、`用户手册.md`（本手册）。
- **命名约定**：日记 `YYYY/YYYY-MM-DD.md`，每天一个文件（遵循 Obsidian 的
  Daily notes 规则）；日记分「用户」「agent」两章——谁做的改动记在谁的名下。

### 04 归档

- **职责**：不再活跃但想保留的内容。
- **入库规则**：任何模块的内容都可归档；单篇归档进当天的日期文件夹；整个
  文件夹归档时保留原文件夹名。
- **分类规则**：按归档当日日期分文件夹，不再细分。
- **命名约定**：`YYYY年MM月DD日/`（中文补零，用当天日期）。

### 扩展模块怎么加（规则登记处）

以后新增的模块，规则就登记在本章（每个模块一节，写法与上面几节相同：
职责 / 入库规则 / 分类规则 / 命名约定）。新模块由你建文件夹发起、agent 来
问规则；哪个模块不用了，agent 也会来问你要不要把规则一并删除或标注停用。

## 三、怎么记录

记录有三条路，选最顺手的那条：

**路线一：随手丢收件箱。**想到什么，直接在 `00 收件箱/` 里新建一个文件写。
不需要写任何头部信息，不需要按格式命名，甚至名字随便起都行——之后整理时
agent 会补齐一切。这是门槛最低的一条路，适合「现在没空讲究」的时刻。

**路线二：直接对 agent 说。**在对话里说出你要记的内容，agent 按规范写好放进
库。几个例子：

| 你说 | agent 做 |
|---|---|
| 「记一下：……」 | 写入 `00 收件箱/`（序号命名，格式齐全） |
| 「摘录：君不见黄河之水天上来……」 | 按本章摘录节的规则进 `02 摘录/` |
| 「这条经验入库，主题是架构设计」 | 合并进 `01 知识/` 对应主题文档的对应章节 |
| 「审阅收件箱」 | 逐条定去向：归属模块 / 归档 / 删除 / 保留 |
| 「把这篇归档」 | 移入 `04 归档/<当天日期>/` |
| 「入库今天手机记的」 | 从暂存库拉取随身端条目写入收件箱 |

**无论哪条路，有一条铁律：你的原话是原样记录的**——agent 不改写、不压缩
你说的话；需要背景说明时它会先问你，经你同意才补「补充」小节。

**关于模板**：`03 系统/模板/` 里有**主题文档模板**（新建知识主题时可套用）。
在 Obsidian 里启用核心插件 Templates、把模板文件夹指向
`03 系统/模板`（初始化时 agent 会引导你做这一步），之后新建笔记时套用模板，
日期之类的信息会自动填好。收件箱**没有**模板——随手丢的地方不该有任何步骤。

## 四、怎么整理

**审阅沉淀**是整理的核心动作，由你发起（对 agent 说「审阅收件箱」），逐条
按第二章的模块规则决定去向：

1. 手册里某个模块收 → 进对应模块；
2. 不再活跃但想留 → 进 `04 归档`；
3. 没价值 → 删除（进回收站，可恢复）；
4. 还没想清楚 → 留在收件箱。

沉淀时 agent 会补全缺的信息（比如用文件的创建时间补上日期）、整理不规范的
地方。**如果你在库里手动改过某个文档、改得不太合规范，agent 在往里写新内容
之前会先问你「要不要先整理一下」**——不会背着你改你的东西。

**日记不用你写，但你的改动会被补记。**`03 系统/日记/` 是库的操作记录，分
「用户」「agent」两章：agent 每次写入、修改、移动、删除、归档都详细记在
agent 章；你手动改动的部分，agent 整理时发现后会依据文件的修改时间和 git
历史**帮你补记**（注明是推断）；想知道「某天这个库发生了什么、谁做的」，
直接翻它。

**待审阅文件**：agent 每批写入内容（入库、沉淀、归档、删除等）后，会在
收件箱放一个 `待审阅-YYYY-MM-DD.md`，列出这批改动的清单和位置，看板上也能
看到它。
你审阅完随手删掉即可——它只是给你的账单，不是内容。agent 的低风险动作
（补日记、调看板）不发账单，只记日记。

**看板**就是根目录的 `看板.md`：收件箱里还有哪些待沉淀的、知识最近更新了
什么，一屏看完。

**归档**：内容不再活跃但你想留着，就让 agent 把它移进 `04 归档/<当天日期>/`。
归档不是删除，随时可以翻出来或移回去。

## 五、怎么找

- **按模块找**：文件树展开就是。每个模块装什么，见第二章——模块规则是唯一
  需要你记住的东西，其余的 agent 替你记；
- **按主题找**：`01 知识/` 下一个主题一个文档，打开文档，章节标题就是索引；
- **看板总览**：打开 `看板.md` 看最近动态和待办；
- **搜索**：Obsidian 自带搜索，找关键词即可——因为沉淀时 agent 会把标签、
  链接补齐，搜索的命中率是有保障的；
- **找「当时发生了什么」**：翻 `03 系统/日记/`。

## 六、记录质量参考

这一章对你手写内容同样适用——记下来的东西是给很久以后的自己看的，标准只有一条：
**那时候的你，读一遍就能懂**。

- **写全**：前因后果、背景、为什么，都写上。一句孤零零的结论，三个月后谁也
  想不起它从何而来；
- **说人话**：不刻意用专业词显得高级。为看起来专业而牺牲好懂，是亏本买卖；
- **别压缩**：宁可长，不要省。尤其不要「把一段话总结成一句」——一句话通常
  说不明白一件事；
- **别用怪比喻**：举例和比喻用日常的、谁都见过的东西。生僻的比喻当时看着
  漂亮，半年后就是谜语。

agent 写的「补充」说明与整理产物也照这四条执行——但**你的原话永远保持原样**，
这四条不用于评判和改动它。如果你觉得 agent 写的哪条佶屈聱牙或者没头没尾，
直接指出来，那是它没达标。

## 七、注意事项

- **删除永远进系统回收站**，可恢复；没有「永久删除」这种操作；
- **白板（canvas）是你的自由空间**：你在库里任何地方建的白板，agent 不会去
  整理、校验或导出它；需要 agent 操作白板时，明说即可；
- **新模块从文件夹开始**：你建了新文件夹，agent 会来问规则、登记进第二章；
  反过来，某个模块的文件夹被删掉时，agent 也会来问你要不要把它的规则一并
  处理——不会默默当作不存在；
- **结构变更有据可查**：模块增减、规则调整发生时，agent 会更新本手册相关
  部分，并把变更（含原因）记入库的内部变更记录 `.config/变更记录.md`——它在
  Obsidian 文件树里不显示，用文件管理器打开库目录即可看到；
- **本手册是规则，也是说明书**：agent 按第二章（模块规则）和第八章
  （agent 约束）执行，你改了这两章，agent 就按新规则来。规则之外的部分
  （这一章和其余章节）随手改不影响它的行为。

> 覆盖，没有差异的项留空即可。你可以直接修改——agent 按你改后的执行。
> （内容规则——什么进哪个模块、怎么分类——在第二章；本章管「agent 怎么
