# 知识库 · 用户手册

> 本手册在首次初始化时由 AI agent 创建，是这个知识库的总说明书：它是什么、
> 东西放哪里、怎么记、怎么整理、怎么找。可以随手修改——它就是给你看的。
> 重复初始化不会覆盖本手册。

## 一、这是个什么知识库

这个知识库存的是**一页纸能写完的东西**：摘抄下来的好句子、验证过确实管用的
经验、还没想清楚但值得先留下的念头。

它**不收**在别处有更合适去处的东西：

- 待办事项——待办软件更擅长催你和打勾；
- 项目文件——它们应该和项目放在一起，放进知识库反而要两边同步，还会过时；
- 可以执行的脚本、项目模板这类东西——它们住在自己所属的仓库里。

为什么这么划？因为一样东西如果在别处有家，知识库里的副本就成了影子：你要花
力气保持两边一致，稍不留神库里那份就过时了，反而骗人。所以这个库只收「没有
更具体去处」的内容——这是它保持轻、保持可信的根本原因。

库由 **Obsidian + AI agent** 共同维护：你在 Obsidian 里自由地写和看；agent
在对话里帮你记录、整理、补全格式。这里有一条贯穿始终的约定——**宽进严出**：

- **宽进**：你往库里放东西没有任何门槛。格式、命名、分类都不是你的义务；
- **严出**：所有规范由 agent 执行。内容要正式沉淀时，agent 会把缺的补齐、
  把不合规范的整理好。

换句话说：规则是约束 agent 的，不是拦住你的。

## 二、库的布局：五个模块，各装什么

打开文件树，你会看到编号从 00 到 04 的五个模块，外加根目录的一个看板文件：

| 位置 | 装什么 | 一句话记住 |
|---|---|---|
| 根目录 `看板.md` | 一屏总览：收件箱待办、最近更新 | 库的正门 |
| `00 收件箱/` | 所有没想清楚、来不及整理的东西 | 先丢这里 |
| `01 知识/` | 验证过的经验与结论，按主题分文档 | 确认管用的 |
| `02 摘录/` | 抄来收藏的诗词、名言、句子 | 抄来的 |
| `03 系统/` | 库自己的痕迹和说明书（日记、模板、本手册） | 库的后台 |
| `04 归档/` | 不再活跃但舍不得删的内容 | 冷存储 |

**关于「有些文件夹看不到」——这是有意的**：空文件夹在 Obsidian 的文件树里
不显示。初始化之后，你只会看到 `01 知识`、`03 系统` 和根目录的看板；
`00 收件箱`、`02 摘录`、`04 归档` 会在**第一次往里写东西时自动出现**。
所以某天你突然发现多了一个文件夹，不是出了怪事，是你第一次用到它了。

编号也有讲究：`03 系统` 和 `04 归档` 永远排在最后两位（归档殿后），将来如果
增加新模块，会插在它们前面顺延编号。你不需要记这条，它只保证文件树的顺序
长期稳定。

## 三、怎么记录

记录有三条路，选最顺手的那条：

**路线一：随手丢收件箱。**想到什么，直接在 `00 收件箱/` 里新建一个文件写。
不需要写任何头部信息，不需要按格式命名，甚至名字随便起都行——之后整理时
agent 会补齐一切。这是门槛最低的一条路，适合「现在没空讲究」的时刻。

**路线二：直接对 agent 说。**在对话里说出你要记的内容，agent 按规范写好放进
库。几个例子：

| 你说 | agent 做 |
|---|---|
| 「记一下：……」 | 写入 `00 收件箱/`（序号命名，格式齐全） |
| 「摘录：君不见黄河之水天上来……」 | 整篇作品建笔记进 `02 摘录/长篇/`；短句追加进 `02 摘录/短篇/` 对应分类 |
| 「这条经验入库，主题是架构设计」 | 合并进 `01 知识/` 对应主题文档的对应章节 |
| 「审阅收件箱」 | 逐条过：沉淀 / 归档 / 删除 / 保留 |
| 「把这篇归档」 | 移入 `04 归档/<当天日期>/` |
| 「入库今天手机记的」 | 从暂存库拉取随身端条目写入收件箱 |

**路线三：随身端捕获。**手机上用 everywhere-note 随手记（@ 它即可），条目
当晚提醒你入库；配置了 GitHub 暂存库的，回到电脑说一句「入库」就自动收进来。

**关于模板**：`03 系统/模板/` 里放了两份笔记模板——**主题文档模板**和
**摘录长篇模板**。在 Obsidian 里启用核心插件 Templates、把模板文件夹指向
`03 系统/模板`（初始化时 agent 会引导你做这一步），之后新建笔记时套用模板，
日期之类的信息会自动填好。收件箱**没有**模板——随手丢的地方不该有任何步骤。

## 四、怎么整理

**审阅沉淀**是整理的核心动作，由你发起（对 agent 说「审阅收件箱」），逐条
决定去向：

1. 是摘抄 → 进 `02 摘录`；
2. 是经验、结论 → 合并进 `01 知识` 的主题文档；
3. 不再活跃但想留 → 进 `04 归档`；
4. 没价值 → 删除（进回收站，可恢复）；
5. 还没想清楚 → 留在收件箱。

沉淀时 agent 会补全缺的信息（比如用文件的创建时间补上日期）、整理不规范的
地方。**如果你在库里手动改过某个文档、改得不太合规范，agent 在往里写新内容
之前会先问你「要不要先整理一下」**——不会背着你改你的东西。

**日记不用你写。**`03 系统/日记/` 里按年存放的文件是库的操作记录：每次
写入、修改、移动、删除、归档，agent 自动追加一行。想知道「某天我对这个库做
了什么」，直接翻它。

**看板**就是根目录的 `看板.md`：收件箱里还有哪些待沉淀的、知识最近更新了
什么、摘录最近添了什么，一屏看完。

**归档**：内容不再活跃但你想留着，就让 agent 把它移进 `04 归档/<当天日期>/`。
归档不是删除，随时可以翻出来或移回去。

## 五、怎么找

- **按模块找**：文件树只有五层编号目录，展开就是。每个模块装什么，见第二章
  那张表——那是这个库唯一需要你记住的东西；
- **按主题找**：`01 知识/` 下一个主题一个文档，打开文档，章节标题就是索引；
- **看板总览**：打开 `看板.md` 看最近动态和待办；
- **搜索**：Obsidian 自带搜索，找关键词即可——因为沉淀时 agent 会把标签、
  链接补齐，搜索的命中率是有保障的；
- **找「当时发生了什么」**：翻 `03 系统/日记/`。

## 六、记录质量参考

这一章对你手写内容同样适用——记下来的东西是给很久以后的自己看的，标准只有一条：
**那时候的你，读一遍就能懂**。

- **写全**：前因后果、背景、为什么，都写上。一句孤零零的结论，三个月后谁也
  想不起它从何而来；
- **说人话**：不刻意用专业词显得高级。为看起来专业而牺牲好懂，是亏本买卖；
- **别压缩**：宁可长，不要省。尤其不要「把一段话总结成一句」——一句话通常
  说不明白一件事；
- **别用怪比喻**：举例和比喻用日常的、谁都见过的东西。生僻的比喻当时看着
  漂亮，半年后就是谜语。

agent 写入库的一切内容也照这四条执行——如果你觉得哪条写得佶屈聱牙或者
没头没尾，直接指出来，那是它没达标。

## 七、注意事项

- **删除永远进系统回收站**，可恢复；没有「永久删除」这种操作；
- **白板（canvas）是你的自由空间**：你在库里任何地方建的白板，agent 不会去
  整理、校验或导出它；需要 agent 操作白板时，明说即可；
- **结构变更有据可查**：模块增减、规则调整都会写进 `03 系统/变更记录.md`；
- **本手册可编辑**：它只是说明书，不是法律。你对库的理解变了，随手改它。
