# 记录规范（本库定制）

> 本文件记录当前知识库的**命名与属性规范**：新建笔记时如何命名、frontmatter
> 怎么写、标签怎么打。目录结构与设计原则见 `知识库架构.md`，内容如何归类见
> `分类规则.md`。

## 目录命名

- 一级目录全部带数字前缀：00 收件箱 / 01 生活系统 / 02 知识系统 / 03 资产系统 /
  04 规范系统 / 05 项目系统 / 06 摘录系统 / 07 看板 / 08 归档 / 09 系统管理；
- 看板、归档与系统管理固定位于最后三位，新增模块插入其前并顺延编号；
- 二级目录不带数字前缀（如 日记 / 日程 / 任务 / 概念原理 / 长篇 / 短篇 / 进行中）。

## 文件命名

| 内容 | 命名 |
|---|---|
| 收件箱记录 | `YYYY-MM-DD 标题.md` |
| 问题记录 | `YYYY-MM-DD 简短描述.md` |
| 知识笔记 | `YYYY-MM-DD 标题.md` |
| 摘录长篇笔记 | `作品名.md`（同名不同作者：`作品名 作者.md`） |
| 摘录短篇聚合 | `名言.md` 等分类名（超 100 条拆分为 `<分类>/<分类> 01.md` 序号递增） |
| 日程 | `YYYY-MM-DD 标题.md` |
| 任务笔记 | `YYYY-MM-DD 任务标题.md` |
| 项目复盘 | `YYYY-MM-DD 项目名 复盘.md` |
| 日记 | `YYYY-MM-DD.md`（在 日记/YYYY-MM/ 下） |
| 规范/资产 | `标题.md`（不带日期前缀） |
| 归档文件夹 | `2026年08月09日/`（中文补零，归档当日） |

其他约定：

- 文件名用简短描述，不用长句；
- 避免点开头文件名；
- 项目文件夹名为 `<项目名>/`，默认含 项目说明/目标/决策记录/研究记录/问题/复盘；
- 来自 GitHub 暂存库的条目沿用收件箱命名与属性规范（`YYYY-MM-DD 标题.md` +
  capture 属性）；

## Frontmatter 核心属性

| 属性 | 说明 |
|---|---|
| `type` | capture / question / knowledge / excerpt / principle / standard / checklist / template / workflow / project / daily / event / task / review / archive / system |
| `capture_kind` | 收件箱子类：随手记 / 灵感 / 待整理内容 / 摘录 |
| `knowledge_type` | 知识类型：概念原理 / 经验方法 / 方案 / 案例 |
| `excerpt_kind` | 摘录形态：长篇 / 短篇 |
| `category` | 摘录分类：长篇（诗词/文言/文学/网络）；短篇（名言/警句/思考/摘抄） |
| `author` / `dynasty` | 摘录作者 / 朝代（诗词文言） |
| `domain` | 领域（知识系统重点使用） |
| `status` | pending / in-progress / done / scheduled / cancelled / active / completed |
| `precipitated` | 问题已沉淀标记（true 或日期） |
| `created` / `updated` | 创建/更新时间；**updated 每次修改必须更新，精确到分钟** |
| `resolved` | 解决/沉淀日期 |
| `due` / `finished_date` | 任务截止/完成时间 |
| `date` / `end` / `location` | 日程时间与地点 |
| `source` / `source_url` | 来源 |
| `project` | 项目归属 |
| `tags` | 层级标签 |

## 标签约定

- 积极打层级标签：`#领域/ai`、`#知识/概念原理`、`#摘录/诗词`、`#项目/xxx`、
  `#日程`；
- 状态类信息优先用 `status` 属性，不依赖状态标签；
- 列表类标签用行内数组 `tags: [a, b]`。

## 硬性要求

1. 修改任何笔记后 `updated` 必须更新（精确到分钟）；
2. 沉淀/归档/相关知识之间建立双向链接；
