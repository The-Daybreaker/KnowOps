# 知识库 · 用户手册

> 本手册由 knowledge-base skill 在首次初始化时生成，面向知识库的使用者。
> 手册可以随手修改或删除，不影响 skill 运行（重复初始化不会覆盖你的手册）。

## 这个知识库怎么用？

你的知识库由 **Obsidian + AI agent** 共同维护：

- **你**：在 Obsidian 里自由写作、浏览、建立链接；
- **AI agent**：在对话里帮你记录、整理、搜索、剪藏、写日记、做视图、导出网页版。

对 agent 说出需求即可，例如：

| 你说 | agent 做 |
|---|---|
| "帮我记录一个问题：……" | 自动归类到 `问题/未解决/`（文件名带日期前缀），写前查重，同步写日志、追加 TODO |
| "记录一下 XX 项目的进展：……" | 自动归类到 `项目/XX/`，同步写日志、追加 TODO |
| "周五下午 3 点项目评审" | 解析时间 → 创建 `日程/` 笔记（带时间属性），含时间信号时自动设提醒 |
| "这个问题我搞懂了 / 已解决" | 展示方案后把问题移入 `问题/已解决/`，标注记录/解决日期、勾选 TODO（先不沉淀） |
| "沉淀这个问题 / 总结成知识" | 判定知识类型交你确认 → 在 `知识/<类型>/` 建知识笔记，双向链接回原问题 |
| "剪藏这篇文章：<URL>" | 先问你放哪个文件夹，再提取正文存为带来源属性的剪藏笔记 |
| "记录今天的日记：……" | 追加到今天的日记（按月自动分目录） |
| "我有哪些待办任务？" | 汇总全库 `- [ ]` 任务（含 TODO.md） |
| "建一个看板 / 打开看板" | 生成/打开 `看板.md`（+ 数据源 `看板.base`，只含已有模块视图，随时更新） |
| "把这篇笔记移到 XX 文件夹" | 先给你看方案，你确认后才移动（链接自动更新） |
| "删掉那篇测试笔记" | 你确认后删除，**进系统回收站，可恢复** |
| "做一个任务视图 / 阅读清单视图" | 按需生成一个专属 Bases 视图（.base），存放位置由你指定 |
| "画一张学习路线画布" | 生成 Canvas 画布（.canvas），存放位置由你指定 |

## 首次使用流程

1. 告诉 agent 你要管理哪个知识库（vault 的实际路径与名称——就是你创建时的名字，
   agent 不会瞎猜）；
2. agent 与你确认后，在 vault 内**隐藏目录 `.config/`**（默认，可改选其他位置）
   生成：
   - `knowledge-base.config.json` —— 配置文件（vault 位置、偏好、可选的导出目录）；
   - `用户手册.md` —— 就是本文件；
   - `log/` —— 操作日志（agent 每次操作都会记一笔，按年月/日切分）；
   - `HTML-Export/` —— 网页版镜像目录（**可选**，初始化时问你是否需要）；
3. 你的 vault 笔记区**始终干净**：知识库无关文件都收在隐藏目录里，不打扰浏览。

## 目录结构（默认，可改）

```
<你的 Vault>/
├── .config/                  # 隐藏目录：配置 / 日志 / 手册 / 网页版镜像（默认）
│   ├── knowledge-base.config.json   # 配置（agent 用）
│   ├── 用户手册.md                   # 本文件
│   ├── log/                          # 操作日志（按年月/日切分）
│   └── HTML-Export/                  # 网页版镜像（可选，手机浏览器打开 index.html）
├── 问题/
│   ├── 未解决/               # 进行中的问题（2026-08-04 文件名.md）
│   └── 已解决/               # 已解决的问题（保留可追溯）
├── 项目/                     # 项目（项目/项目名/...）
├── 日志/                     # 日记（2026-08/2026-08-03.md 这样按月分）
├── 日程/                     # 日程（2026-08-05 项目评审.md，带时间属性）
├── 知识/                     # 沉淀的知识，按类型分（经验/原理/工具/设计/规范/案例/模板）
├── 看板.md                   # 看板总览：问题/任务/日程/知识/项目/剪藏/日记一屏看（可选）
└── TODO.md                   # 唯一待办文件：记录问题/项目时自动追加，解决后自动勾选
```

> 剪藏、模板、附件、Bases、Canvas 没有固定目录——它们是"文件类型"，放在哪个
> 文件夹由你说了算，agent 每次会先问你或按你的指令存放。

**问题的一生**：随手一句话记录 → 进 `问题/未解决/`；学到后说一句"解决了" →
agent 把它移入 `问题/已解决/`，补上记录日期、解决日期，并把 TODO.md 里那条待办
勾掉（勾掉后自动收进 TODO.md 底部「已完成」折叠区，最新的在最上面）。想沉淀成
知识时再说"沉淀这个问题"→ agent 建议知识类型（经验/原理/…）经你确认后，在
`知识/` 下建一篇笔记，并和原问题互相链接——原问题一直保留着，随时可查。

**日程与提醒**：说"周五下午 3 点项目评审"，agent 就建一条日程笔记；如果这条
日程或待办带着明确时间、或你说"提醒我"，agent 会自动设置定时提醒，到点主动
来问你进度。看板（`看板.md`）把问题、任务、日程、知识等一屏汇总，内容随笔记
实时更新——你改了状态，看板立刻反映，不用手动刷新。

**内容一定分门别类**：agent 会把每条记录自动归到 问题 / 项目 / 日志 / 日程 /
剪藏 等模块；如果它判断不出属于哪一类，会先问你放哪，不会丢进"未分类"文件夹
（知识库里没有收件箱）。

## 设计理念（为什么这样搭）

- **Obsidian 原生**：日记、模板、Bases、Canvas 全是 Obsidian 自己的能力，
  agent 通过官方接口调用，不重复造轮子；
- **Vault 是唯一数据源**：没有第二份数据库、没有同步映射，文件即真相；
- **配置驱动**：路径、目录、习惯全在 `knowledge-base.config.json` 里，换电脑、
  换库都能迁移；
- **知识库无关文件不打扰笔记**：配置/日志/手册/网页版镜像默认收在隐藏目录
  `.config/` 里，不写入笔记区；
- **安全**：
  - 删除进系统回收站（回收站里能找回来），不做彻底删除；
  - 修改、移动、删除已有内容前，agent 必须先给你看方案、经你同意；
  - 新建内容不需要同意，但会先查相似内容，发现雷同由你定夺；
  - 如果你的 vault 是 Git 仓库，agent 每次写完自动提交一次（只提交，绝不帮你建仓库）。

## 网页版（HTML-Export）是什么？（可选功能）

如果初始化时启用了网页版镜像，每次 agent 新增 / 修改 / 删除笔记后，都会自动把
vault 镜像成一套独立 HTML 放到 `HTML-Export/<库名>/` 下（默认在 `.config/` 内），
目录结构与 vault 一致，首页是 `index.html`。把手机连上同一目录（或用你喜欢的
同步方式拷过去），浏览器打开即可阅读——双链可点击、流程图可渲染，不需要安装
Obsidian。不需要这个功能的话，初始化时跳过即可，随时可以让 agent 补开。

## 常见问题（FAQ）

**Q：agent 删错了怎么办？**
A：打开系统回收站还原即可。agent 的删除永远进回收站，不做彻底删除。

**Q：我直接改 vault 里的文件，agent 知道吗？**
A：知道。vault 就是唯一数据源，agent 每次操作都是实时读取的。网页版镜像会在
agent 下次写操作后自动对齐（也可以随时让它"全量重建网页版"）。

**Q：可以管多个库吗？**
A：可以。配置里注册多个 vault 后，说"用工作库做……"或让 agent 切换默认库即可。

**Q：Obsidian 没打开时 agent 能操作吗？**
A：写入类操作需要 Obsidian 运行（会尝试自动拉起，拉不起来会提醒你打开）。
网页版导出不要求 Obsidian 打开。

**Q：配置文件坏了 / 想换电脑？**
A：配置文件是纯文本 JSON，可备份、可手改；到新环境让 agent 重新初始化即可，
不会动你 vault 里的任何内容。

**Q：日记为什么在某个年月子目录里？**
A：日记按 `年月/日期` 两层目录自动归档（如 `日志/2026-08/2026-08-03.md`），
这是初始化时约定的格式，可在配置中调整。

**Q：`.config/` 目录能改名或挪走吗？**
A：能。初始化时可改选其他位置（如 vault 上级目录）；改名/挪走后记得同步配置
中的偏好（configDir）与各脚本的路径。
