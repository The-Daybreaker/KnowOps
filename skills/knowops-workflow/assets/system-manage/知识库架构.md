# 知识库架构（本库定制）

> 本文件描述当前知识库的模块架构与设计原则，是 `knowops-workflow` 默认规范的
> 落地实例。内容以实际记录为准，模板小节可增删改；变更时同步更新「变更记录」。

## 模块图

```
00 收件箱    —— 捕获入口（随手记 / 灵感 / 待整理内容）
01 生活系统  —— 发生什么（日记 / 日程 / 任务 / 问题）
02 知识系统  —— 理解了什么（概念原理 / 经验方法 / 方案 / 案例）
03 资产系统  —— 可以复用什么（模板 / 工作流）
04 规范系统  —— 应该遵守什么（原则 / 标准规范 / 检查清单）
05 项目系统  —— 正在创造什么（进行中 / 已完成 / 项目复盘）
06 看板      —— 一屏总览（Bases 数据库驱动）
07 归档      —— 不再活跃但保留（按归档日期文件夹）
08 系统管理  —— 知识库自身的操作系统文档
```

## 设计原则

1. 一级模块长期稳定，不频繁调整；
2. 分类变化用标签、属性、双向链接与索引页解决，不靠不断新建目录；
3. 新模块必须满足：内容规模足够、有独立生命周期、有独立工作流；
4. 模块之间通过输入 → 处理 → 输出连接；
5. Agent 负责理解与整理，人负责创造与思考；
6. 目录最多三层是知识系统内部的软性建议，不全局强制；
7. 归档与系统管理固定位于最后两位，新模块插入其前并顺延编号。
