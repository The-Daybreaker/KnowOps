# knowops-workflow 知识库管理（工作流程规范）

## 定位

本 skill 是**工作流程规范（workflow）**：描述知识库应当如何组织、各模块的流程
应当怎么走，供用户与 agent 共同查阅。本 skill 可独立使用：只安装本 skill，即可
依据本规范管理知识库，具体执行由 agent 的通用能力完成。

所有目录名与文件名规则均为**可配置默认值**（见「配置」），实际以用户确认的
配置为准。

## 红线（工具无关，任何执行方式均适用）

1. **删除永远进系统回收站且可恢复**：删除只进入系统回收站，不做无法恢复的彻底
   删除。
2. **新建并初始化知识库时，优先使用 git 管理**：建立版本管理，便于回溯与同步。
3. **创建任何新内容前先做相似检查**：避免重复内容。
4. **尽量使用已有模块**：内容优先进入已有模块，不因单次内容新增模块。

## 知识库模型

- **模块路由**：任何记录请求都应先判断内容类型与未来用途，再按「分类原则」
  路由；**简短、零碎、临时的顿悟/灵感/想法/不明确内容默认进入 00 收件箱**；
  明确完整的问题、日程、项目请求仍直达对应模块。
- **创建前相似检查**：创建任何新内容前，先执行相似检查；发现高相似内容时，
  决策为合并 / 跳过 / 仍写入之一（不强制阻断）。
- **稳定核心 + 可插拔模块**：一级模块长期稳定；新增模块需满足"内容规模足够、
  有独立生命周期、有独立工作流"三个条件，编号顺延至归档与系统管理之前。
- **目录不承担全部导航**：文件夹只负责"放在哪里合理"；动态导航依靠标签、
  属性、双向链接、索引页与 Agent 智能整理。

## 模块总览（默认，可配置）

| 模块 | 职责 | 内部结构 |
|---|---|---|
| 00 收件箱 | 捕获入口：简短/零碎/临时内容 | 随手记 / 灵感 / 待整理内容 |
| 01 生活系统 | 发生什么 | 日记 / 日程 / 任务 / 问题 |
| 02 知识系统 | 理解了什么 | 概念原理 / 经验方法 / 方案 / 案例 |
| 03 资产系统 | 可以复用什么 | 模板 / 工作流 |
| 04 规范系统 | 应该遵守什么 | 原则 / 标准规范 / 检查清单 |
| 05 项目系统 | 正在创造什么 | 进行中 / 已完成 / 项目复盘 |

> **编号规则**：一级目录全部带数字前缀；**归档与系统管理固定位于最后两位**，
> 未来新增模块插入它们之前并顺延编号。

## 分类原则（不问"哪个目录"，问"未来怎么用"）

1. **用于解释**（是什么/为什么）→ `02 知识系统/概念原理`
2. **用于指导行动**（应该怎么做/遵守什么）→ `04 规范系统`（应遵守）或
   `02 知识系统/经验方法`（个人做法）
3. **用于复制**（可复用的骨架/流程）→ `03 资产系统/模板` 或 `工作流`
4. **用于解决类似问题**（怎么解决一类问题）→ `02 知识系统/方案`
5. **只是参考**（真实发生过的事例）→ `02 知识系统/案例`

知识回答"这个东西是什么"，项目回答"我如何把它应用到现实"。

## 知识库专属规则（08 系统管理，每次操作前必读）

- **文件**：`08 系统管理/Agent规则.md`（默认位置，随配置可改）。初始化为本库
  创建全套系统管理文档（来源 `assets/system-manage/`），**目标已存在则绝不覆盖**
  （询问后决定保留或合并）。
- **作用**：`Agent规则.md` 记录本库插件集成规则、额外红线、额外操作要求；
  `分类规则.md` 记录本库分类约定；`命名规范.md`、`Frontmatter规范.md` 记录
  命名与属性约定；`知识库架构.md` 记录模块图与设计原则；`变更记录.md` 记录
  结构变更历史；`用户手册.md` 面向知识库使用者。
- **读取时机**：**每次操作前必须读取 `Agent规则.md`**（与「创建前相似检查」
  并列的操作前环节）；涉及分类时读取 `分类规则.md`；涉及命名/属性时读取
  对应文件。
- **优先级**：本库专属规则是默认流程的**补充与覆盖**——与本规范冲突时以本库
  专属规则为准。
- **维护**：插件变动、新增模块、新红线、新偏好时及时更新对应文档并写入
  `变更记录.md` 与操作日志。

## 模块流程

### 00 收件箱（捕获入口）

- **捕获**：简短/零碎/临时的顿悟、灵感、想法、不明确内容默认写入：
  - `随手记/`：无明确类型的快速记录；
  - `灵感/`：顿悟、创意、新想法；
  - `待整理内容/`：URL 素材、草稿、未完成材料、暂时说不清的内容。
  文件命名 `YYYY-MM-DD 标题.md`，子目录内平铺；frontmatter 至少含
  `type: capture` + `capture_kind` + `created` + 标签。
- **审阅维护**（用户发起为主，可配定时提醒）：逐条判断价值：
  1. 有价值且类型明确 → 按「分类原则」沉淀到目标模块（整理成正式笔记，
     原收件箱文件删除）；
  2. 有价值但暂不明确 → 留在 `待整理内容/`；
  3. 无价值 → 删除；
  4. 过时 → 归档到 `07 归档/<归档当日日期>/`。
- **沉淀去向**：知识/规范/资产/项目/问题/任务等按「分类原则」路由；沉淀时
  遵守目标模块的命名与属性规则，并建立双向链接。

### 01 生活系统（发生什么）

- **日记**：原生日记，按时间切分（默认 `日记/YYYY-MM/YYYY-MM-DD.md`）。
- **日程**：`日程/YYYY-MM-DD 标题.md`；属性 `type: event` + `date`（开始时间
  ISO）+ `end`/`location`（可选）+ `status`（scheduled/done/cancelled）+
  「日程」标签；完成/取消只改属性不移动；含时间信号时联动提醒。
- **任务**：任务文件夹内**每任务一篇笔记**（`任务/YYYY-MM-DD 任务标题.md`，
  `type: task` + `status`（pending/done）+ `due` + `created/updated`），作为
  看板数据源；同时维护 `任务/TODO.md` 人工快捷清单（`- [ ]` 未完成列表 +
  底部「已完成」折叠块）。**两边互为镜像、双向同步**：TODO.md 的新增/勾选/
  取消/删除会被识别并同步到任务笔记，任务笔记的改动也同步回 TODO.md；冲突
  无法判定时询问用户，不静默覆盖。
- **问题**：`01 生活系统/问题/未解决|研究中|已解决|已沉淀/YYYY-MM-DD 简短描述.md`：
  - 未解决：已记录、未开始或搁置；
  - 研究中：正在主动学习/排查/推进；
  - 已解决：`status: done` + `resolved`（解决日期），TODO 同步勾选；
  - 已沉淀：沉淀知识笔记后原问题移入，`precipitated: true` + 双向链接，
    原问题长期保留，可再归档。

### 02 知识系统（理解了什么）

- 四类：`概念原理`（是什么/为什么）、`经验方法`（个人实践做法与技巧）、
  `方案`（针对一类问题的解决设计）、`案例`（真实发生过、可供参考）。
- 文件命名 `YYYY-MM-DD 标题.md`；frontmatter 含 `type: knowledge` +
  `knowledge_type` + `domain`（领域）+ `created` + `source` + 标签。
- **二级目录按领域**（如 `概念原理/AI/`），领域同时写入 frontmatter `domain`；
  领域目录**用到才建**。
- **增长触发（仅知识系统）**：同一目录 <50 篇不拆；50~150 篇建立领域二级
  目录；>150 篇评估三级。二级目录建立时自动创建 `<领域>索引.md`（如
  `AI索引.md`）。
- 相关知识之间互相链接，确保知识索引。

### 03 资产系统（可以复用什么）

- `模板/`：可复制骨架（项目模板、笔记模板等），文件不带日期前缀；
- `工作流/`：可重复执行的流程/脚本/自动化，脚本与工具归入此类；
- 附件仍不预设目录（位置以用户指令为准）。

### 04 规范系统（应该遵守什么）

- `原则/`：决定方向，高度抽象、长期稳定、适用范围广、不依赖具体工具；
- `标准规范/`：定义要求（命名要求、Frontmatter 要求、流程要求）；
- `检查清单/`：保证执行（发布前、归档前、收件箱审阅前等）；
- 文件不带日期前缀。

### 05 项目系统（正在创造什么）

- `进行中/<项目名>/`：项目默认包含 `项目说明.md`、`目标.md`、`决策记录.md`、
  `研究记录.md`、`问题.md`、`复盘.md`；
- 项目完成 → 整个项目文件夹移入 `已完成/`；
- 复盘 → 在 `项目复盘/` 建 `YYYY-MM-DD 项目名 复盘.md` 并链接回项目；
- 长期不活跃/结束项目可整体归档到 `07 归档/<日期>/<项目名>/`。

### 06 看板（数据库驱动）

- 形态：`看板.md`（嵌入容器）+ `看板.base`（views 数组承载各板块视图，
  每个视图各自过滤条件），**初始化默认创建**。
- 默认视图：收件箱-待整理、问题-未解决、问题-研究中、任务-未完成、
  日程-即将到来、项目-进行中、知识-最近沉淀。
- 可扩展：用户可随时要求新增/修改视图；模块首次出现内容时自动增补视图；
  日程一律 table 视图（不使用 calendar）。

### 07 归档

- 所有模块（收件箱、问题、项目等）都可归档；
- 文件夹按**归档当日日期**命名：`2026年08月09日/`（中文补零）；
- 单篇文件平铺；项目等文件夹整体归档时保留原文件夹名；
- **懒加载创建**：目录按需创建（空文件夹在文件树中不显示）；首次归档时先创建
  `07 归档/<归档日期>/`（目标目录不存在时先创建再写入/移入），归档后即可见；
- 归档动作记入操作日志与 `08 系统管理/变更记录.md`。

### 08 系统管理

- 文件：`知识库架构.md`、`分类规则.md`、`命名规范.md`、`Frontmatter规范.md`、
  `Agent规则.md`、`变更记录.md`、`用户手册.md`；
- 模板存于 skill `assets/system-manage/`，初始化复制进库，保证各库初始化一致；
- `Agent规则.md` 每次操作前必读；其余按需读取。

## 插件集成（通用机制，不写死具体插件）

- skill 不写死任何插件名、流程或顺序；一切以**初始化时用户确认并写入
  `08 系统管理/Agent规则.md` 的规则**为准。
- 初始化时：扫描当前知识库可用的插件/扩展能力 → 逐个向用户确认是否纳入工作流、
  执行时机与顺序（如"修改后先版本提交、再同步"）→ 写入 `Agent规则.md`。
- 插件信息默认只存于 `Agent规则.md`（人读、可编辑）；自动化脚本确实需要
  机器可读数据时再补写配置，不提前落盘。
- 插件变动（安装/卸载/改规则）：更新 `Agent规则.md` 并记入 `变更记录.md`；
  每次操作前必读，操作后按其中规则执行。

## 联动动作（收件箱沉淀 / 问题 / 项目 / 知识 / 日程后执行）

1. **写日志**：在当日操作日志追加一行（`<时间> [类型] 动作与目标`）；
2. **任务双轨同步**：涉及任务时，更新任务笔记与 `TODO.md` 并保持一致；
3. **建立双向链接**：沉淀/归档/相关笔记之间建立链接；
4. **插件规则**：按 `Agent规则.md` 中配置的规则执行（如版本提交、同步）；
5. **看板反映确认**：看板已启用时确认实时反映正确。

## 操作日志

- 位置：`<logDir>/<YYYY-MM>/<YYYY-MM-DD>.md`（默认 `.config/log/`，隐藏目录）；
- **每次操作（含读取/搜索）追加记录**；日志不参与看板聚合与 HTML 导出。

## 操作后流程（每次写入 / 修改后执行）

1. 写日志；
2. 任务双轨同步（涉及任务时）；
3. 看板反映确认；
4. 插件规则（版本提交 / 同步等，按 `Agent规则.md`）；
5. 反馈：写入位置、建立的链接、后续建议。

## 初始化向导（首次接入知识库，按序逐项确认，不一次性抛所有问题）

1. 确认 vault 实际路径与名称（已注册 vault 供点选；未注册时按应用流程注册）。
2. 展示并确认默认目录结构（8+1 模块）与配置位置（默认 vault 内隐藏目录
   `.config/`）；**内容模块目录按需创建（懒加载）**：初始化只预置 08 系统管理
   与 06 看板，其余模块在首次写入时自动出现。
3. 写入配置文件（schema 版本跟随 skill 版本）。
4. 扫描当前知识库可用的插件/扩展能力。
5. 逐个确认插件集成规则（是否纳入、时机与顺序）。
6. 复制 `assets/system-manage/` 模板到 `08 系统管理/`（已存在不覆盖，询问
   保留/合并）。
7. 将插件集成规则写入 `Agent规则.md`（默认不写入机器配置）。
8. 创建 `06 看板/看板.md` + `看板.base`（默认视图）。
9. 配置原生日记（文件夹与日期格式），验证路径形态。
10. 可选：HTML 镜像导出（确认启用与位置；复制脚本副本到 `.config/scripts/`）。
11. 新建并初始化知识库时优先使用 git 管理：检查是否为 git 仓库，不是则由用户决定是否建仓。
12. 写首条操作日志，反馈汇总（配置路径、插件规则、系统管理文档、看板、
    日记格式、导出状态）。

> 旧库接入：检测到与默认结构不一致的已有内容时，**不自动迁移**，现场向用户
> 确认处理方式（保持 / 部分调整 / 全量重构），结论写入 `Agent规则.md`。

## 配置与 HTML 导出

- **配置文件**：`knowops-workflow.config.json`（默认 `.config/`，可改位置；旧文件名
  `knowledge-workflow.config.json` 仅兼容发现，初始化只写新文件名）。
  键包括：`version`（跟随 skill 版本）、`defaultVault`、`vaults`、`exportRoot`
  （仅启用 HTML 导出时）、`cliPath`（工具路径，初始化时确认）、`preferences`
  （各模块目录与偏好，见 `references/properties.md`）。
- **HTML 镜像导出**（可选组件，配置了 `exportRoot` 才启用）：把 vault 内笔记
  镜像导出为独立 HTML，增量同步、删除的笔记同步移除镜像；隐藏目录不导出；
  `08 系统管理` 属可见笔记，参与导出。
- **库内脚本副本（可改造）**：初始化时把导出/配置脚本复制到 `.config/scripts/`，
  此后导出一律运行库内副本；skill 内脚本只是默认模板；升级时副本与模板不一致
  则询问用户（覆盖/保留/对比）。
- **导出范围**：`.config/scripts/html-export.json` 控制 include/exclude（glob），
  隐藏目录始终不导出。

## 脚本一览（本 skill 自带组件，`--json` 输出机器可读结果，`-h` 查看参数）

| 脚本 | 用途 |
|---|---|
| `scripts/kb_config.py` | 配置与多 vault：init / find / add-vault / remove-vault / list / set-default / path / get / set / validate |
