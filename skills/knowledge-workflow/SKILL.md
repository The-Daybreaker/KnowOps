# knowledge-workflow 知识库管理（工作流程规范）

## 定位

本 skill 是**工作流程规范（workflow）**：描述知识库应当如何组织、各模块的流程
应当怎么走。它面向"流程"而非"执行者"——**不是对 agent 的行为要求，也不是对
任何工具的操作要求**；本文件不涉及工具操作细节（如何执行写入/删除、操作红线、
具体语法）。

本文档供用户与 agent 共同查阅：用户据此了解知识库的组织方式，agent 据此执行
流程。所有目录名与文件名规则均为**可配置默认值**（见「配置」），实际以用户
确认的配置为准。

## 知识库模型

- **模块路由**：任何记录请求（再笼统也要分类）都应先判定模块类型，再按规则
  路由；类型与判定线索见「模块路由表」。
- **无收件箱**：判断不出类型时，自行判断归属（可新增模块，见「模块路由表」
  无法判定行），不存在静默兜底目录。
- **创建前相似检查**：创建任何新内容前，先执行相似检查；发现高相似内容时，
  决策为合并 / 跳过 / 仍写入之一（不强制阻断）。
- **文件类型位置不预设**：剪藏 / 附件 / 模板 / 看板 / 画布等，存放位置以用户
  指令为准，不设固定目录。

## 模块路由表

| 类型 | 判定线索 | 目标位置（配置键 → 默认） | 联动 |
|---|---|---|---|
| 问题 | "问题 / 没搞懂 / 不懂 / 为什么 / 待复盘 / bug" | `<questionDir>/未解决/` → `问题/未解决/` | 日志 + TODO + 提醒判断 + log |
| 项目 | "项目 / 工程 / 学习项目 / 课题" | `<projectsDir>` → `项目/<项目名>/` | 日志 + TODO + log |
| 日程 | "日程 / 会议 / 约 / 几点 / 什么时候 / 提醒我" | `<scheduleDir>` → `日程/` | 提醒 + log |
| 剪藏 | 给出 URL | 用户指令指定位置（不预设目录） | 日志 + log |
| 日记 | "日记 / 今天" | 原生日记（`<dailyFolder>` → `日志/`） | log |
| 知识 | "沉淀 / 总结 / 整理成知识" | `<knowledgeDir>/<类型>/` → `知识/<类型>/`（类型新增需确认） | 链接 + log |
| 任务 | "待办 / 要做 / 别忘了" | `<todoFile>` → `TODO.md`（vault 根） | 提醒判断 + log |
| 无法判定 | 不属于上述任何一类 | 自行判断，可新增 | 按判定结果 |

**通用流程**：判定模块 → 相似检查 → 组装结构化内容（frontmatter 属性集见
`references/properties.md`，含义是本库设计）→ 创建 → 联动动作 → 操作后流程。

## 模块流程

### 问题（未解决 → 已解决 → 沉淀分离）

- **记录**：文件名统一 `YYYY-MM-DD 简短描述.md`（日期为问题出现日期；文件名用
  简短描述，如 `2026-08-04 FPGA同步异步复位问题.md`，不要用长句）；纯文字单
  文件，含图片/附件时建同名文件夹存放；frontmatter 至少含 `type: question`、
  `status: pending`、`created`（= 问题出现日期）、领域标签。
- **解决**（触发：已解决 / 已复盘 / 已学会；与沉淀分离，解决不自动沉淀）：
  更新属性 `status: done` + `resolved`（解决日期）+ `updated`（精确到分钟，
  `created` 保持问题出现日期不改）；移入 `<questionDir>/已解决/`（文件名不变，
  含资源的整个文件夹移动）；勾选 TODO 中对应条目；写当日日志。
- **沉淀**（触发：另行发起沉淀（"沉淀这个问题 / 总结成知识"），仅已解决问题可沉淀）：
  判定知识类型（初始 7 类见「知识」；不适合现有类型时可提出新类型，新增需经
  确认）；创建知识笔记并**双向链接回原问题**；回写原问题追加"已沉淀"链接；写日志。
  **原问题保留在已解决文件夹，不删除、不移动**。

### 知识（原「知识与经验」）

- 位置：`<knowledgeDir>/<类型>/YYYY-MM-DD 标题.md`（日期为沉淀日期，标题简短）；
  frontmatter：`type: knowledge` + `knowledge_type` + `created` + `resolved` +
  `source` + 领域标签；正文含**经验总结**小节。
- 类型：初始 7 类（经验 / 原理 / 工具 / 设计 / 规范 / 案例 / 模板），
  **用到才建**子目录（不预建空目录）；类型可动态扩展（新增需经确认）。

### 日程

- **录入**：记录内容（如"周五下午 3 点项目评审"）→ 解析日期时间 → 创建
  `<scheduleDir>/YYYY-MM-DD 简短标题.md`（日期 = 日程日期）；frontmatter：
  `type: event` + `date`（开始时间 ISO）+ `end` / `location`（可选）+
  `status`（scheduled / done / cancelled）+ 必须含「日程」标签（看板聚合依据）。
- **完成 / 取消**：只更新 `status`（done / cancelled）+ `updated`（精确到分钟），
  **不移动文件**。
- **提醒联动**：录入含明确时间信号或明确要求提醒时创建定时提醒（见「自动化提醒」）。

### 任务（TODO）

- 统一 `- [ ]` 语法；待办集中在 `<todoFile>`（默认 `TODO.md`，vault 根）；
  问题/项目记录时自动追加 `- [ ] [<类型>] <标题> → [[<标题>]]（<日期> 记录）`。
- **勾选完成**后：把已完成条目移入 TODO.md 底部「已完成」折叠块（默认折叠），
  最新完成排最上、完成越久越靠下；历史遗留的块外已完成条目在下次重组时一并收进。
- 含时间信号的待办：自动创建定时提醒，条目旁标注「已设提醒」（见「自动化提醒」）。

### 日记（原生日记，按月切分）

- 目录与格式来自配置 `preferences.dailyFolder`（默认 `日志/`）/
  `preferences.dailyFormat`（默认 `YYYY-MM/YYYY-MM-DD`）。
- 分类路由的记录动作会自动写一行日志（见「联动动作」），无需重复写。
- 复盘场景按"问题解决 → 知识沉淀"流程处理，不只改属性。

### 网页剪藏

- 从 URL 提取干净正文 → 组装笔记：`type: clip` + `source_url` + `source_domain`
  + `clipped_at`（ISO 时间）+ 正文；标题取页面标题；打来源/领域标签。
- **存放位置**：剪藏位置不预设，按归属方指定的位置存放；相似检查 → 创建 →
  操作后流程。

### 附件与模板

- 附件：存放位置不预设（以归属方指定为准），复制后在笔记中引用。
- 模板：按归属方指令使用/创建；skill 不内置个人模板。

## 联动动作（问题 / 项目 / 剪藏 / 知识记录后执行）

1. **写日志**：在当日日记追加一行记录（`- <时间> [<类型>] <标题> → [[<标题>]]`）；
   当日日记或日志目录不存在时先创建。
2. **追加 TODO**（仅问题 / 项目）：`todoFile` 不存在先创建，再追加待办条目。
3. **建立双向链接**（知识 / 剪藏 / 沉淀时）：链接原问题、相关笔记。
4. **自动化提醒判断**（追加 TODO 后）：按「自动化提醒」规则判断时间信号。

## 自动化提醒（平台无关）

触发：追加待办或创建日程（含时间信号）后，判断是否创建定时提醒。

- **强信号**（直接创建）：明确要求提醒（"提醒我 / 到点提醒 / 别忘了"）；含具体时刻
  （"明天下午 3 点"）；含周期词（"每天 / 每周五 / 每月"）。
- **弱信号**（先确认）：仅含截止日期（"8 月 10 日前交报告"）→ 确认是否创建提醒。
- **无信号**（不创建）：纯任务描述，只记录不建提醒。

创建：使用当前平台可用的自动化 / 定时提醒能力（一次性：具体日期时间；周期：
周期规则）；提醒内容注明"读取对应 TODO/日程条目与相关笔记，汇报进度并确认完成
状态"。创建后 TODO 条目旁标注「已设提醒」；取消/查看按标题或时间匹配，经确认后
操作；创建与取消均记入操作日志。

## 看板（可选组件，用户要求时创建）

- **形态**：`看板.md` + `看板.base` 两个文件，命名统一为「看板」——`看板.base`
  是看板数据源（`views` 数组承载各板块视图，每个视图各自过滤条件），看板.md
  嵌入 `![[看板.base#视图名]]`；Bases 是 Obsidian 原生唯一的实时聚合方案，
  必须有 .base 数据源（看板.md 只是嵌入容器）。
- **动态板块（只加载已有模块）**：生成时检查各模块（问题 / 任务 / 日程 / 知识 /
  项目 / 剪藏 / 日记）是否已有内容，**只为有内容的模块创建视图**；板块过滤要点
  见 `references/bases.md`。
- **及时更新**：Bases 视图读取笔记属性，问题解决 / 任务勾选 / 日程状态 / 沉淀 /
  剪藏等操作**自动实时反映**，无需重建；操作后流程负责确认反映正确，且板块
  **首次出现内容**时为其增补视图并更新看板文件。
- **日程一律用 table 视图**（按 `date` 排序 +「即将到来」`date >= today()` 过滤），
  不使用 calendar（Bases 不支持该视图类型）。

## 属性、标签与双向链接

- 核心属性集（含义与设计）见 `references/properties.md`；用户可自由增删，
  唯一硬性例外：`updated` 每次修改必须更新（精确到分钟）。
- **积极打层级标签**（硬性要求）：`#领域/fpga`、`#知识/经验`、`#课程/小梅哥` 等，
  为聚合与检索建立索引。
- **建立双向链接**（硬性要求）：沉淀链接原问题、剪藏链接相关笔记、相关知识
  互相链接；发现相关内容时主动补链。

## 操作日志

- 位置：`<logDir>/<YYYY-MM>/<YYYY-MM-DD>.md`（默认 `log/`）；日志目录不在笔记
  浏览范围内，不参与 HTML 导出与看板聚合。
- **每次操作（含读取/搜索）追加记录**：`- <HH:MM> [<操作类型>] <目标路径或简述>`；
  日志目录不存在先创建。

## 操作后流程（每次写入 / 修改后执行）

1. **写日志**：追加当日操作日志记录（见「操作日志」）。
2. **看板反映确认**：看板已启用时，确认本次操作已实时反映；板块首次出现内容时
   增补对应视图并更新看板文件（见「看板」）。
3. **版本提交**：vault 已是版本仓库时提交本次变更；不是仓库时仅提示（本流程不
   代为建仓）。
4. **反馈**：说明结果（写入位置、建立的链接、后续建议）。

## 初始化向导（首次接入知识库，按序逐项确认，不一次性抛所有问题）

1. vault 在接入前已存在、名称不统一，流程只读取实际路径与名称。
2. 确认 vault 实际路径与名称（已注册 vault 供点选；未注册时按应用流程注册）。
3. 确认配置位置：默认 **vault 内隐藏目录 `.config/`**（配置 / 操作日志 / 用户
   手册 / HTML 导出默认存放处；`config` 为通用配置目录名，点前缀使其在文件树
   中隐藏）；可改选其他位置（如 vault 上级目录）。写入规则：**允许写入隐藏目录
   `.config/`，不写入用户笔记内容区、不影响笔记浏览**；`.config/` 整体不进
   HTML 导出、不参与看板聚合。
4. 是否需要 **HTML 镜像导出**（可选组件）：不需要则跳过该功能；需要时确认
   导出位置（默认 `<vault>/.config/HTML-Export/`，可改）。
5. 是否还有其他 vault（逐个注册，可设默认）。
6. 展示默认目录结构（见 `references/properties.md` 目录模板）供确认或修改，
   结果写入偏好。
7. 执行初始化：创建配置文件（`knowledge-workflow.config.json`，默认写 `.config/`），
   注册 vault，写入偏好。
8. 复制用户手册（`assets/user-manual.md` → 知识库文件夹，默认文件名
   `用户手册.md`；**目标已存在则绝不覆盖**（仅提示））。
9. 检查 vault 是否已是版本仓库：是 → 后续按「操作后流程」提交；否 → 可自行
   建仓（本流程不代为初始化仓库）。
10. 配置原生日记（文件夹与日期格式），完成后验证日记路径形态。
11. 首次全量 HTML 导出（若第 4 步需要）。
12. 是否创建看板（可选组件）：需要 → 按「看板」小节动态生成；不需要 → 记录
    偏好，可随时按需补建。
13. 反馈：配置路径、vault 列表、导出位置（如有）、手册位置、日记格式验证结果、
    看板状态。

## 配置与 HTML 导出

- **配置文件**：`knowledge-workflow.config.json`（默认 `.config/`，可改位置）。
  键包括：`version`、`defaultVault`、`vaults`、`exportRoot`（仅启用 HTML 导出
  时）、`cliPath`（工具路径，初始化时确认）、`preferences`
  （目录与偏好，见 `references/properties.md` 目录模板）。配置管理通过随附
  脚本完成（见「脚本一览」）；旧版本配置可迁移。
- **HTML 镜像导出**（可选组件，配置了 `exportRoot` 才启用）：把 vault 内笔记
  镜像导出为独立 HTML（`<exportRoot>/<vault名>/<相对路径>.html` + 索引页
  `index.html`），增量同步、删除的笔记同步移除镜像；不依赖应用打开状态。
  操作日志在 `.config/` 内，不纳入导出。

| 脚本 | 用途 |
