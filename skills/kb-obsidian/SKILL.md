# kb-obsidian Obsidian 操作规范

## 定位

本 skill 承载**所有对工具的要求**：① 对所有工具的统一规范与红线（跨工具通用
纪律）；② Obsidian 专有操作规范（vault 与 CLI 相关）。**不含知识库业务规则**
（模块路由、问题生命周期、沉淀流程等由 **knowledge-workflow** 规范负责）——
执行知识库相关操作时，流程与规则以 knowledge-workflow 规范为准，本 skill 只
规定执行层面（怎么操作、操作红线、何时征求决策）。

通用性说明：本文与 references 中的行为描述为**跨平台通用表述**，具体版本行为
可能存在差异，**使用时需自行验证**；完整语法以 Obsidian 官方文档为准。

## Part 1 对所有工具的统一规范与红线（跨工具通用）

1. **修改 / 移动 / 重命名 / 删除已有内容前**：先展示变更方案（源 → 目标、受
   影响的内容与链接），**征得用户同意**后再执行。
2. **永不执行 `git init`**：vault 是 Git 仓库时只提交；不是仓库则提示用户可自行
   建仓，绝不代为初始化。
3. **不假设路径与名称**：vault 名、目录名、文件位置一律以配置与用户确认为准，
   一切配置驱动；配置缺失时询问用户，不猜测。
4. **删除纪律**：删除只用工具的删除接口，**默认进系统回收站（可恢复）**；严禁
   使用永久删除参数；严禁用 `rm` / `Remove-Item` / `os.remove` 等绕过工具接口
   的删除方式；删除前告知用户"进回收站、可恢复"。
5. **创建前相似检查**：创建新内容前先搜索相似内容，高相似时展示给用户决策
   （合并 / 跳过 / 仍写入）。
6. **直接文件访问例外清单**（默认一律走工具接口，以下场景可直读直写文件，且
   必须在回复中说明原因）：
   1. 工具不可用，且用户明确同意继续；
   2. 需对原始文件做格式校验（JSON / YAML / Canvas）；
   3. 二进制附件导入（工具不支持二进制时）；
   4. 批量读取源文件（如 HTML 导出，本身不依赖应用运行）；
   5. 超长内容（命令行参数可能被截断）：工具创建占位文件后直写完整内容；
   6. 隐藏目录（点开头，如 `.config/`）内文件：工具接口无法访问，可直写
      （如操作日志、用户手册、配置文件）。
7. **重要写入后回读校验**：写入 / 修改 / 移动后读回核对，确认内容与结构正确。
8. **记录归属决策**：无法判定记录归属哪一模块时，询问用户归属，由用户决定
   写入哪一模块；不自创模块、不静默放置。新增模块 / 知识类型同样先向用户确认。
9. **信息以用户给出为准**：记录内容（如日程的时间地点、问题的描述、剪藏存放
   位置）由用户给出，以其提供的信息为准，不自行臆造；信息不足时询问补齐。

## Part 2 Obsidian 专有规范

### CLI 发现与连接

- 路径解析顺序：配置中的 `cliPath` → 系统 PATH → 平台常见安装位置
  （Windows 常见安装目录 / macOS Applications）。CLI 与 Obsidian 应用同装。
- CLI 是**非 headless** 的：连接已运行的 Obsidian；未运行时先尝试自动拉起并
  轮询等待，拉起失败则提示用户手动打开 Obsidian。
- 关键操作前先做环境自检（CLI 可用、vault 已注册），失败给出可执行修复提示。
- 多 vault：操作时按 vault 名称指定目标库（名称来自配置，与 Obsidian 注册名一致）。

### 笔记操作（核心命令与规范）

- **创建**：路径参数用 `path=`（或 `name=`）指定；多行内容直接传；特殊字符
  处理见「CLI 怪癖与注意」；创建后回读校验。
- **读取 / 搜索**：按路径读取；搜索用于相似检查、内容检索、列表类查询。
- **追加**：向已存在笔记追加内容。
- **移动 / 重命名**：移动前展示方案并征得同意；工具会自动更新相关链接；
  目标目录不存在先创建；含附件的笔记连同文件夹整体移动。
- **删除**：见 Part 1 第 4 条；删除后若启用镜像导出，同步更新导出。
- **属性更新**：修改笔记时同步更新 `updated` 属性（精确到分钟），状态类信息
  用 `status` 属性（便于聚合过滤）。

### CLI 怪癖与注意（实测经验，通用化表述，需自行验证）

- **换行处理**：content 多行优先用真实换行；转义序列（`\n`）可能被转成真实
  换行——因此 **JSON 类内容（.canvas）无法经 CLI 正确写入**（字符串内的字面
  `\n` 会被破坏），一律直接写文件（例外清单第 2 条）。
- **盘符陷阱（Windows）**：转义换行形式下，`<字母>:\n`（如 `tags:\n`）可能被
  误判为盘符路径、`\` 变 `/`——frontmatter 列表改用行内数组（`tags: [a, b]`）。
- **含单引号内容**：命令行传参含单引号（如 `1'b0`）时 shell 拼接易错；
  建议用 Python subprocess 传参（参数列表直传，不经 shell 拼接）。
- **点开头文件名**：`.xxx.md` 可能解析异常（创建报错但文件已生成、删除找不到），
  避免使用点开头文件名。
- **日记目录不存在**：`daily` 追加类命令会报目录不存在——先创建日记目录再操作。
- **长参数截断**：命令行参数超长（约 4000 字符以上）可能被截断导致内容缺失——
  用「长内容两步写入」。
- **`eval` 副作用**：`eval` 返回对象时可能报无害错误（副作用已生效）。

### 长内容两步写入（>4000 字符）

1. 用工具 `create` 先建占位文件（创建动作仍走工具接口）；
2. 文件系统直写完整内容（例外清单第 5 条，回复中说明原因）；
3. 回读校验完整内容。

### 日记设置（原生日记，按月切分）

- 日记目录与格式来自配置（如 `日志/` + `YYYY-MM/YYYY-MM-DD`）。
- 设置流程（工具无专用命令时）：
  1. 持久化配置（写入 `.obsidian/app.json` 的 daily-notes 设置）；
  2. 内存实例设置（立即生效）；
  3. 日记目录不存在时先创建目录。
  三步缺一不可（仅持久化不刷新运行中实例；仅改内存重启后丢失）；工具无法
  设置时给用户一次性人工指引（设置 → 日记 → 日期格式 / 新笔记位置）。
- 设置后验证日记路径形态（应形如 `日志/2026-08/2026-08-03.md`）。

### 网页剪藏

1. 用可用的正文提取工具（如 defuddle）从 URL 提取干净 Markdown；不可用时
   降级为直接抓取或手动整理。
2. 组装笔记：`type: clip` + `source_url` + `source_domain` + `clipped_at`
   （ISO 时间）+ 正文；标题取页面标题；打来源 / 领域标签；相关时建立双向链接。
3. 存放位置以用户指令为准（不预设目录）；确认后相似检查 → 创建 → 回读校验。

### 附件

- 工具不支持二进制附件时：直接复制到用户指定的 vault 内位置（例外清单第 3 条，
  回复中说明原因），随后在笔记中用 `![[<文件名>]]` 引用。
