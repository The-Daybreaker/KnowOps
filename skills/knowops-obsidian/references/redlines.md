# 对所有工具的统一规范与红线（Part 1 完整展开）

> 本文件是跨工具通用纪律的完整版。默认一律走工具官方接口操作；以下场景允许
> 直接读写文件，且**必须在回复中说明原因**。

## 通用操作纪律

1. **改删前征求同意**：修改 / 移动 / 重命名 / 删除已有内容前，先展示变更方案
   （源 → 目标、受影响的链接与文件），征得用户同意后再执行；含附件的笔记连同
   文件夹整体处理时一并说明。
2. **永不 `git init`**：vault 已是 Git 仓库时按约定提交（如 `docs: <简述>`）；
   不是仓库则提示用户可自行建仓，绝不代为初始化仓库。
3. **不假设路径与名称**：vault 名、目录名、文件位置一律以配置与用户确认为准
   （一切配置驱动）；配置缺失或不确定时询问用户，不猜测。
4. **创建前相似检查**：创建新内容前先搜索相似内容；高相似时展示给用户决策
   （合并 / 跳过 / 仍写入），不强制阻断、不强制标题规范。
5. **重要写入后回读校验**：写入 / 修改 / 移动后读回核对内容与结构；校验失败
   则修正后重写并重新校验。
6. **记录归属决策**：简短/零碎/临时的顿悟、灵感、想法、不明确内容默认写入
   `00 收件箱`（随手记/灵感/待整理内容，见 knowops-workflow 规范）；仍无法
   判定归属时询问用户，由用户决定写入哪一模块；不自创模块、不静默放置。
   新增模块 / 知识类型同样先向用户确认。
7. **信息以用户给出为准**：记录内容（如日程的时间地点、问题的描述、素材存放
   位置）由用户给出，以其提供的信息为准，不自行臆造；信息不足时询问补齐。
8. **插件规则必读**：每次操作前读取 `08 系统管理/Agent规则.md`，操作后按其中
   插件集成规则执行（如版本提交、云同步）；插件安装/卸载/改规则先经用户确认，
   并同步更新该文件与 `变更记录.md`。

## 删除纪律（硬性）

- 删除**只用工具的删除接口**，默认进系统回收站（可恢复）；
- 严禁使用**永久删除参数**（绕过回收站彻底删除）；
- 严禁 `rm` / `Remove-Item` / `os.remove` 等任何绕过工具接口的删除方式；
- 删除前征得用户同意，并告知"进系统回收站、可恢复"。

## 直接文件访问例外清单

| # | 场景 | 说明 |
|---|---|---|
| 1 | 工具不可用 | 工具未安装 / 目标应用未运行，且用户明确同意继续 |
| 2 | 格式校验 | 需对原始文件做 JSON / YAML / Canvas 结构校验 |
| 3 | 二进制附件导入 | 工具不支持二进制内容时直接复制文件 |
| 4 | 批量读取源文件 | 如 HTML 镜像导出：本身不依赖应用运行，需批量读源 |
| 5 | 超长内容（>4000 字符） | 命令行参数可能被截断：工具先建占位文件，再直写完整内容 |
| 6 | 隐藏目录（点开头）内文件 | 工具接口无法访问（如 `.config/` 下的日志 / 配置 / 脚本副本），可直写 |

> 例外场景执行后必须在回复中说明原因；其余情况一律走工具接口。

## 安全边界

- 知识库无关文件（配置 / 日志 / 脚本副本 / 导出产物）默认写入隐藏目录（如
  `.config/`），**不写入用户笔记内容区、不影响笔记浏览**；
- 知识库规则文档（架构/分类/命名/Frontmatter/Agent规则/变更记录/用户手册）为
  **可见笔记**，位于 `08 系统管理/`，由初始化模板创建、用户可编辑；
- 不对用户笔记做批量扫描式改写；修改前先看方案。
